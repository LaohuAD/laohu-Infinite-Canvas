# RunningHub 国内站/国际站模型目录设计

## 目标

让 API 设置中的 RunningHub 模型拉取同时满足两件事：不再因为错误的模型列表端点或 GitHub 短暂失败而只剩少量 LLM；不把国际站的模型猜成国内站已开放。

## 事实边界

- 模型 endpoint、参数、枚举和输出类型只读取官方 `developer-kit/model-registry.public.json`。
- 该注册表没有 region/site/availability 字段，因此不能凭模型名称推断国内或国际可用性。
- 两站官方“标准模型”页面只用于建立地区公开状态，不从页面反推 endpoint 或 Schema。
- 注册表收录但当前站点公开目录没有对应记录的模型，标记为“目录未列出”，不标记为“不可用”。这样既不误导，也不会屏蔽可能对特定账号隐藏开放的模型。

## 交互

- 拉取后的模型选择器仍显示注册表的完整可接入目录。
- 每个 RunningHub 模型显示当前站点公开目录状态：“目录已列出”或“目录未列出”。目录状态不等同于账号级调用验证。
- 目录未列出的模型允许用户主动选择，但不默认勾选，并给出简短提示；最终可用性以该账号真实提交结果为准。
- 国内站固定使用 `www.runninghub.cn` 与国内专用 Key，国际站固定使用 `www.runninghub.ai` 与国际专用 Key；地址不可手工交叉配置。旧通用 Key 只作为国际站历史配置的读取兼容，新设置不得继续写入。
- 切换国内/国际站后，目录状态、LLM 网关和用户已启用清单同步切换；两站启用清单继续互不污染。

## 后端流程

1. 优先获取官方 `developer-kit/model-registry.public.json`，校验结构后解析。
2. 远程失败时使用仓库中已校验的最近官方快照，不使用手写的少量模型充当“完整目录”。
3. 获取当前站点官方公开标准模型页面，仅用精确官方标识匹配可公开确认的注册表项。
4. LLM 目录独立从当前地区网关获取；LLM 拉取失败不得让标准模型目录降级为 LLM-only。
5. 删除未在官方契约中存在的 `/openapi/v2/models` 请求和相关“Key 已验证”误导。公开目录读取成功只说明接入配置和官方目录可读，Key 由首次真实任务验证。

## 验收

- 国内站和国际站返回同一份官方 Schema 可接入目录，但地区公开状态不同。
- 断网或 GitHub 不可达时，仍能从已校验快照获得完整目录。
- 任何代码路径都不请求 `/openapi/v2/models`。
- 国内 LLM 使用 `.cn`，国际 LLM 使用 `.ai`。
- 拉取和切换站点不会自动恢复用户已删除的模型。
