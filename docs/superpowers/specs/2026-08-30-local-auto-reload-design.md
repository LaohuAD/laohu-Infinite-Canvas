# 本地服务自动重载设计

## 目标

解决项目代码已经更新、浏览器也已刷新，但 3000 端口仍由旧 Python 进程提供旧后端逻辑的问题。完成后，用户通过 macOS 或 Windows 正式启动入口运行项目时，Python 源码发生变化会自动重载服务；静态资源继续通过现有无缓存 HTML 响应和动态资源版本立即生效。

## 现状依据

- `mac-启动服务.command`、`mac-启动服务.sh` 和 `run.bat` 最终都执行 `python main.py`。
- `main.py` 当前以 ASGI 应用对象启动 Uvicorn，未开启 reload；进程启动后不会重新读取修改过的 Python 文件。
- HTML 响应已经使用 `Cache-Control: no-cache`，脚本和样式 URL 会按资源修改时间生成版本标识，因此静态文件不需要重启后端。
- 模型能力档案由 `ModelCapabilityRegistry` 在请求时读取，画布、设置、素材和缓存数据也属于运行时数据，不能因为它们频繁写入而触发服务重启。

## 方案

### 1. 单一启动源

在 `main.py` 提供本地服务启动配置函数。直接运行 `python main.py` 时，使用字符串形式的 `main:app` 启动 Uvicorn，并默认开启自动重载。macOS 和 Windows 启动脚本不各自实现文件监控，只负责选择正确的 Python 后调用同一入口。

这样可以避免三套启动方式行为不一致，也满足 Uvicorn 只有在应用使用导入字符串时才能开启 reload 的要求。

### 2. 受控监控范围

自动重载只处理 Python 源码：

- 包含：项目源码中的 `*.py`。
- 排除：`.venv/`、`python/`、`.git/`、`assets/`、`data/`、`cache/`、`backups/`、输出目录和测试临时目录。
- HTML、CSS、JavaScript 不触发后端重启，继续使用动态缓存版本。
- 模型能力 JSON、API 设置、画布 JSON、素材索引和任务状态不触发重启，避免正常使用时形成重启循环。

### 3. 默认行为与退出入口

- 正式本地启动默认启用自动重载。
- 环境变量 `INFINITE_CANVAS_AUTO_RELOAD=0`、`false`、`no` 或 `off` 时关闭，便于特殊部署或故障排查。
- 启动终端明确显示自动重载是否启用以及监控对象，避免用户无法判断当前运行模式。

### 4. 任务与状态

Python 文件更新后允许立即重载。正在轮询的生成任务可能中断，但项目已有启动恢复逻辑，会把未完成画布任务标记为待恢复，不把中断伪装成成功或失败。静态文件更新不重启，不影响正在运行的任务。

### 5. 首次迁移

这项功能写入代码时，已经运行的旧进程本身无法知道新增了自动重载，因此实现完成后需要最后手动重启一次 3000 端口。此后由 reload 父进程持续监控 Python 更新，不再依赖人工提醒。

## 跨平台要求

- macOS：验证 `mac-启动服务.command` 与 `mac-启动服务.sh` 最终进入自动重载模式。
- Windows：静态检查 `run.bat` 仍通过项目 Python 或系统 Python 执行 `main.py`，不使用 POSIX 专用监控命令。
- 监控路径通过 `pathlib` 或 Python 字符串配置生成，不拼接平台专用分隔符。
- `watchfiles` 保持在公共依赖中；Windows 安装脚本继续安装 `uvicorn[standard]`。

## 验收标准

1. 自动化测试证明默认开启重载，显式环境变量可以关闭。
2. 自动化测试证明 Uvicorn 使用 `main:app` 字符串，而不是应用对象。
3. 自动化测试证明监控包含 Python 文件，同时排除运行时数据和虚拟环境目录。
4. macOS 实际启动 3000 端口后修改一个专用测试 Python 文件，服务子进程自动重载且 `/api/app-info` 仍可访问。
5. HTML、CSS 或 JavaScript 修改不会触发 Python 重启，刷新页面仍获取新资源版本。
6. `mac-启动服务.command`、`mac-启动服务.sh` 与 `run.bat` 都无需各自维护第二套监控逻辑。

## 不在本次范围

- 不实现生成任务跨进程无缝续跑。
- 不监控素材、画布、缓存、API Key 或普通业务数据。
- 不为生产型多进程部署强制开启 reload；这类环境可通过环境变量关闭，或直接使用外部 ASGI 启动命令。
