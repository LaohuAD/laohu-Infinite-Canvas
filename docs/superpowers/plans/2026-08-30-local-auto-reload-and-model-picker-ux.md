# 本地自动重载与模型选择器体验实施计划

> 本计划在当前脏工作区内执行，只修改与本次需求直接相关的文件，不提交或覆盖用户运行数据。

## 目标

1. 本地通过 `python main.py`、macOS 启动脚本或 Windows 启动脚本运行时，Python 源码更新后自动重载后端；静态页面继续依赖动态缓存版本刷新，不因素材或数据写入反复重启。
2. RunningHub 模型选择器使用面向用户决策的状态文案，并提供批量选择能力，让用户无需逐个勾选数百个模型。

## 任务一：先锁定自动重载契约

- 在后端测试中增加默认开启、环境变量关闭、`main:app` 字符串入口、仅监控 Python 以及运行时目录排除测试。
- 先运行新增测试，确认当前实现失败。
- 在 `main.py` 增加纯配置函数，再让 `__main__` 统一调用该配置。
- 在 README 中说明默认自动重载和关闭方法。

## 任务二：先锁定模型批量选择与可用性文案

- 增加中英文文案和页面契约测试，要求显示“建议选择 / 可能不可用”，并保留准确的解释提示。
- 增加批量选择行为测试：全选建议模型、全选全部模型、清空三种操作必须更新同一份选择状态。
- 在模型选择器顶部增加批量操作区；全选全部后仍复用应用阶段的一次风险确认，不逐条打断用户。
- 给状态标签增加解释性悬停提示，并同步调整中英文确认文案。

## 任务三：沉淀项目规则

- 在 `AGENTS.md` 写入可复用规则：技术来源状态不能直接作为用户决策标签；大批量模型清单必须提供批量选择和清空能力。

## 任务四：验证真实使用路径

- 运行定向测试、JavaScript 语法检查、完整测试和 `git diff --check`。
- 手动重启一次当前 3000 端口，使旧进程进入新的 reload 父子进程模式。
- 用专用临时 `.py` 文件验证子进程自动更换，用临时 `.js` 文件验证静态修改不会触发 Python 重启。
- 通过 `http://192.168.1.253:3000` 验证接口可访问、页面拿到新脚本，并检查模型选择器的真实布局和批量按钮。
