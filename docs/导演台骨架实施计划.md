# 视频导演台共享骨架 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在现有智能画布上建立“通用导演台”和“MiniMax H3 导演台”两个入口，共用同一套视频 Clip、素材库、单轨时间线、连接 Clip、预览、运行和分片导出骨架。

**Architecture:** 新增纯函数化的导演台领域核心，负责数据归一化、时间线排序、连接 Clip 输入推导和导出命名；智能画布只负责交互和展示。普通 Clip 复用现有视频生成节点的能力档案、模型筛选、参数面板、预检和执行接口；MiniMax H3 通过适配器继续复用本地 ComfyUI、RunningHub 工作流/AI 应用。旧 `smart-minimax` 只做单向迁移，不再作为新版运行数据源。

**Tech Stack:** 原生 JavaScript UMD、HTML/CSS、FastAPI/Pydantic、FFmpeg、Python `unittest`、Node.js contract tests。

---

## 实施边界

- 第一阶段只生成和管理视频片段，不承担字幕、配乐、多轨合成、转场和成片剪辑。
- 角色—音色绑定仅保留在《导演台骨架设计》中，本阶段不实现字段、界面或运行逻辑。
- 普通 Clip 和连接 Clip 位于同一轨道；连接 Clip 以覆盖层形式落在普通 Clip 或空白区上。
- 所有输入素材在 Clip 下方按文本、图片、视频、音频分组垂直罗列。
- 导出是独立片段压缩包，不拼接成一个视频；所有片段统一按时间顺序命名为 `项目名-clip-NNN.ext`。

## 完成标准

只有同时满足以下条件，第一阶段才算完成：两个入口共用同一数据/交互骨架；旧 MiniMax 数据可单向迁移；普通和连接 Clip 都能通过真实能力档案选模并生成；连接输入遵守 1 秒边界和左右对称规则；素材垂直列在 Clip 下方；连接 Clip 与普通 Clip 同轨覆盖；播放和保存重开一致；导出只包含按时间顺序命名的独立片段；角色—音色绑定没有混入本阶段代码。
