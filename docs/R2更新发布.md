# R2 更新发布配置

## 已创建的云端资源

- 标准存储桶：`laohu-infinite-canvas`，桶本身保持私有。
- Worker：`laohu-infinite-canvas`，负责介绍页和发布文件读取。
- 网站域名：`https://infinitecanvas.lao-hu.com`，已绑定并验证 HTTPS 200。
- Worker 源码：`tools/canvas-site-worker.mjs`；绑定变量使用 `RELEASES`。
- GitHub Variables 已写入 `R2_BUCKET` 和 `R2_PUBLIC_URL`。
- GitHub Secrets 已配置 `R2_ENDPOINT`、`R2_ACCESS_KEY_ID`、`R2_SECRET_ACCESS_KEY`，并通过仓库密钥列表确认存在；不在项目或文档中保存明文。
- 发布凭据名为 `github-infinite-canvas-release`，仅允许读写 `laohu-infinite-canvas` 桶内对象，长期有效，可在 Cloudflare R2 API 令牌页撤销。
- 网站入口与存储桶的接通、首次发布及客户端安装验收完成前，不对外宣称自动更新已可用。

GitHub 主分支的 VERSION 变化时，由 `.github/workflows/publish-r2.yml` 构建更新包并发布；也支持手动触发。R2 仅保存程序发布文件，不上传用户 Key、配置、画布和素材。代码历史保留在 GitHub。

在 GitHub 仓库 Settings → Secrets and variables → Actions 设置：

| 类型 | 名称 | 内容 |
| --- | --- | --- |
| Variable | R2_BUCKET | 已创建的标准存储桶名 |
| Variable | R2_PUBLIC_URL | 已绑定的 HTTPS 自定义域名，末尾不加路径 |
| Secret | R2_ENDPOINT | Cloudflare 提供的 S3 API endpoint |
| Secret | R2_ACCESS_KEY_ID | 限定该桶的对象读写凭据 ID |
| Secret | R2_SECRET_ACCESS_KEY | 对应密钥，仅填入 GitHub Secrets |

更新入口为 `R2_PUBLIC_URL/canvas-releases/latest.json`。为此路径设置绕过 CDN 缓存规则，版本目录允许长期缓存。先上传完整包和版本清单，再切换 latest。保留当前版、上一版；更老文件经过七天宽限期后，在下一次发布时清理。不能为整个桶设置无差别删除规则。

本地运行 `python tools/publish_r2.py` 只打包，输出 `cache/release/`；添加 `--publish` 才上传。路径处理兼容 macOS 和 Windows。包包含所有根目录程序模块、启动脚本、依赖清单、前端及模型能力档案。同版本号不得重复发布不同提交。

发布脚本和客户端已随 `2026.09.10` 提交到主分支，首次 GitHub Actions 发布成功。新版客户端优先读取 R2 发布清单，固定从本站版本路径下载，校验包大小、SHA-256、逐文件摘要、路径、版本与 Python 语法后，复用本地备份和安装恢复流程。R2 校验失败不降级到其他源。尚未发布或检测不可达时可以检查自己的 GitHub 仓库；旧 ModelScope 仓库不再参与自动更新。

`static/release_update.py` 是发布端和客户端共用的文件范围与包校验模块。放在 static 是为了首次升级兼容：旧客户端只下载 main.py、VERSION 和 static，也必须能取得此模块。后续完整更新同时包含模型能力档案和根目录运行模块。

依赖清单变化时当前实现会拒绝自动覆盖，提示使用完整安装流程并重新安装依赖；不会在正在运行的 Python 环境中静默升级依赖。现有 3000 服务未被重启；新后端在独立 3011 测试端口验证过 app-info 的 R2 地址。Windows 路径校验与同名大小写冲突已有测试，本轮未在真实 Windows 系统执行安装。
