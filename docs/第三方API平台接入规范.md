# 第三方 API 平台接入规范

## 1. 目的

这份规范用于把第三方平台的 API 文档转换成智能画布能够稳定使用的平台配置。目标不是把模型名称塞进下拉框，而是完成以下闭环：

```text
用户保存平台地址和 Key
→ 拉取模型目录
→ 用户选择要启用的模型
→ 为启用模型建立模型家族和任务变体
→ 映射到统一输入、参数和输出
→ 通过 dry-run 静态契约测试
→ 画布显示可运行模型
```

**目录发现不等于可运行。** 模型出现在上游目录，只能证明平台返回了这个名称。只有输入角色、参数、输出、请求字段和适配器全部有证据并通过 dry-run 后，模型才可以进入画布的可运行列表。

这份文档同时是自定义平台的操作契约：用户可以把它和第三方官方 API 文档一起交给本地 Agent（例如 Codex），由 Agent 在当前项目中完成适配。适配完成后，用户仍然在 API 设置中自行填写 Key、拉取模型和选择启用清单；项目不会替用户保存第三方密钥，也不会因为目录中出现模型就自动开放未经验证的能力。这里要明确区分两种维护责任：项目维护者维护共享的 Manifest、能力档案和受控适配器；添加自定义平台的用户维护自己的平台文档、凭据和启用清单。自定义平台的配置不会自动同步给其他用户。

这份规范是可迭代的初版，不是一次性冻结的接口承诺。每完成一个官方平台或自定义平台，都要用实际官方 Schema、请求字段、错误响应和参数展示对照验证；如果规范无法表达真实差异，先更新规范、统一语义或 Manifest Schema，再更新对应适配器和测试。

## 2. 用户与维护者的职责

- 用户负责：新增平台、填写 Base URL 和 Key、拉取模型、从文本/图片/视频/音频分类中保留自己要使用的模型。
- 用户可以在 API 设置中删除不想使用的模型。删除只改变当前平台的画布启用清单，不删除官方能力档案、Provider Manifest 或历史画布快照；该模型不得再出现在新建节点候选中。
- 本地 Agent 或平台维护者负责：阅读第三方官方文档，创建 Provider Manifest、能力档案和必要的平台适配器，并完成静态测试。
- 画布负责：只读取 API 设置中仍然启用且运行准备度为 `ready` 的模型。用户从 API 设置删除某个模型后，该模型立即退出画布候选列表，但历史画布快照仍保留原模型信息。

### 2.1 用户实际要做什么

用户不需要修改画布节点代码，也不需要为每个模型手工填写“这个参数对应哪个输入框”。一次自助接入只需要准备：

1. 第三方平台的官方 API 文档地址，最好同时提供模型目录、认证、任务提交、任务查询、结果下载和错误码文档。
2. 用户自己的平台名称、稳定平台 ID、Base URL 和 API Key。Key 只填写在 API 设置，不交给 Agent，也不写入 Manifest。
3. 允许本地 Agent 读取当前项目文件；Agent 只修改该平台的 Manifest、能力档案、受控适配器和契约测试。

适配完成后，用户在 API 设置中执行“保存 Key → 拉取模型 → 选择模型 → 应用到模型列表”。拉取全部模型只是建立该用户自己的上游目录；用户可以在文本、图片、视频、音频分类中停用不需要的模型。停用后的模型不会出现在新建画布节点，也不会被真实调用，但能力档案、平台适配器和历史画布快照仍然保留。其他用户只有在自己的项目中完成同一平台适配、填写自己的凭据并启用模型后，才会看到该平台的候选。

这里的“停用/删除模型”是用户自己的启用清单操作，不是从项目中删除平台适配代码。它只改变当前用户当前平台的可用模型投影：

```text
上游全部目录
→ 用户按文本/图片/视频/音频选择保留项
→ 当前用户启用清单
→ 能力档案与适配器均 ready 的画布候选
```

因此，用户可以先完整拉取，再删掉暂时不用的模型；删掉后它不会出现在发布节点下拉框，也不会触发真实请求。以后重新需要时，可以再次从目录选择；历史画布仍保留原模型 ID 和能力快照，不能静默换成相似模型。

修改前依次阅读：

1. `AGENTS.md`
2. `docs/智能画布节点重构PRD.md` 第四章
3. `docs/model-capabilities/能力档案维护规范.md`
4. `docs/model-capabilities/平台适配说明.md`
5. `data/model_capabilities/provider-manifest.schema.json`
6. `model_capabilities.py`
7. `static/js/smart-model-capabilities.js`
8. `main.py` 中现有平台适配器与 `/api/model-capabilities`

不得为新平台复制一套画布节点。平台差异应进入 Manifest、能力档案和适配器，画布继续消费统一语义。

## 4. 模型身份

每个模型按三层登记：

- **模型家族**：用户看到的产品名称，例如 `Seedance 2.0 Fast`。
- **任务变体**：文生视频、首帧、首尾帧、多参考、视频编辑等真实能力。
- **部署路由**：真实 `model_id`、endpoint、地区或计费通道。

同一模型家族可以包含多个任务变体。画布根据用户选择的操作模式和当前输入素材的类型、角色、数量，选择唯一变体；存在歧义时要求用户选择，不允许猜测。

## 5. Provider Manifest

Manifest 必须通过 `data/model_capabilities/provider-manifest.schema.json`。核心区域包括：

- `provider`：平台 ID、名称、版本、维护者和官方文档。
- `transport`：HTTP 或本地 CLI、协议、Base URL、允许域名和超时。
- `auth`：认证位置和前缀，只描述规则，不保存真实 Key。
- `catalog`：模型目录地址及字段路径。
- `families`：模型家族、任务变体、输入、参数、输出、证据和请求映射。
- `task_protocol`：同步或异步提交、查询、取消和结果解析。
- `errors`：平台错误码到统一错误的映射。
- `security`：允许域名、重定向、上传目标和脱敏字段。

Manifest 不允许内嵌 JavaScript、Python、Shell 或任意可执行模板。复杂签名、上传和轮询必须放入项目审核过的平台适配器。

### 5.1 用户自助接入流程

自定义平台按以下顺序操作，不能跳过能力证据和静态验证：

1. 在 API 设置点击“新增平台”，填写平台名称、稳定 ID 和 Base URL。
2. 复制 Agent 指令，在其中补充第三方官方 API 文档地址，再将指令、本文件、`data/model_capabilities/provider-manifest.schema.json` 和第三方官方文档一起交给本地 Agent。
3. Agent 先读取现有节点契约，再生成 Provider Manifest 草稿；Manifest 只描述平台，不包含 Key、Cookie、本机绝对路径或可执行脚本。
4. Agent 将官方模型接口归并为模型家族和任务变体，补齐输入角色、参数、输出、请求映射、任务状态和证据来源。
5. Agent 通过 Schema、语义引用、允许域名、脱敏和请求快照校验；不确定的字段标记为 `unknown` 或 `needs_profile`，不能凭名称补全。
6. 用户在 API 设置保存 Key，点击“拉取模型”取得上游目录，再点击“选择模型”确定文本、图片、视频、音频四类启用清单并保存。
7. 画布只读取当前平台启用且 `readiness=ready` 的模型；未启用、待补档案或适配器未完成的模型保留在 API 设置状态中，但不进入可运行候选。
8. 平台文档或接口变化时，先生成新版本并做差异检查；校验失败继续使用最近有效版本，不得清空已有配置。

### 5.2 给本地 Agent 的实际交付方式

用户已经把项目拉取到本地后，可以在项目根目录打开终端，把第三方官方 API 文档地址和下面的指令一起交给 Codex。文档既可以使用 URL，也可以直接告诉 Agent 读取项目内的 `docs/第三方API平台接入规范.md` 和 `data/model_capabilities/provider-manifest.schema.json`；不要把 Key、Cookie、完整 Authorization 头或本机登录态粘贴给 Agent。

Agent 完成代码和本地测试后，用户回到 API 设置完成三步：

1. 保存该平台的 Key 或本机 CLI 登录状态。
2. 点击“拉取模型”，检查平台返回的文本、图片、视频、音频分类；分类不可靠时以官方 Schema 和能力档案为准。
3. 点击“选择模型/应用到模型列表”，只保留真正需要的模型；模型行上的“删除”表示停用当前用户，不删除平台适配。

API 设置中的“查看规范”面向人类阅读，“查看 Schema”面向 Agent 或程序读取，“复制 Agent 指令”只生成不含密钥的任务文本。三者和第三方官方文档共同构成一次接入的输入材料。Agent 指令应明确要求 Agent 只修改当前平台的受控接入文件和测试，不把 Key 写入 Manifest、能力档案、画布、导出包或日志。

### 5.3 Agent 的映射边界

第三方字段必须先转换为平台无关的标准请求，再由适配器转换为第三方请求。映射至少分为四层：

| 第三方文档信息 | 标准层字段 | 画布表现 | 运行时处理 |
| --- | --- | --- | --- |
| 模型或 endpoint | `family_id`、`variant_id`、`model_id` | 模型家族和能力变体 | 按输入角色、数量和操作模式解析唯一变体 |
| 文本、图片、视频、音频输入 | `inputs.*.media_type`、`role`、`min/max` | 节点端口和素材映射 | 后端再次校验类型、角色和数量 |
| 下拉、布尔、数字、字符串参数 | `parameters.*.type/options/min/max` | 动态参数控件 | 只发送当前档案声明且通过校验的值 |
| 提交、查询、结果和错误 | `task_protocol`、`outputs`、`errors` | 运行状态、结果素材和日志 | 由受控适配器负责请求、轮询、落盘和脱敏 |

Agent 不得把第三方字段名直接散落在节点前端，也不得仅凭模型名称猜测参数。文档没有证据的字段必须标记为 `unknown` 或 `needs_profile`；只有完成映射和本地契约测试后，才能将模型标为 `readiness=ready`。

这里的“删除模型”是用户级停用，不是删除平台适配代码。若用户重新需要该模型，可以再次从上游目录选择；若模型能力本身发生变化，则必须更新 Manifest、能力档案和适配器后再启用。

### 5.4 第三方文档到画布的映射工作表

Agent 处理第三方文档时，必须先建立一份“官方字段 → 标准字段 → 画布位置 → 平台字段”的映射工作表，再生成 Manifest 或修改适配器。工作表可以是 Agent 的中间产物，不作为运行时密钥或用户素材存储。

| 映射步骤 | 必须回答的问题 | 输出到项目的位置 | 未确认时的处理 |
| --- | --- | --- | --- |
| 目录发现 | 如何列出模型、分页、输出类型和真实 ID？ | `catalog`、目录解析夹具 | 标记 `catalog_unverified`，不进入画布 |
| 模型归并 | 哪些上游 ID 属于同一个产品家族？后缀代表什么任务变体？ | `families[].family_id`、`variants[]` | 不确定就分开登记，不按名称猜测合并 |
| 输入映射 | 文本、图片、视频、音频分别是什么角色、数量和顺序？ | `inputs`、标准请求输入 | 标记 `needs_profile`，不生成对应端口 |
| 参数映射 | 字段是字符串、数字、布尔、枚举还是媒体输入？选项的显示名与提交值是什么？ | `parameters`、`request_mapping` | 不生成可运行控件，不把 `0/1` 猜成“否/是” |
| 任务映射 | 提交、查询、取消和结果下载如何关联？ | `task_protocol`、`outputs` | 只能做目录和请求快照校验 |
| 错误映射 | 官方错误码表示鉴权失败、参数错误、限流还是任务失败？ | `errors` | 保留脱敏原文摘要，禁止静默重试或重新提交 |

画布只消费标准语义，不直接读取第三方字段名。标准请求至少包含 `provider_id`、`family_id`、`variant_id`、真实 `model_id`、`node_type`、`operation`、输入素材及其角色/顺序、有效参数、能力档案版本和请求映射版本。第三方的 `input2`、`image_url`、`frames`、`task_id` 等字段只能出现在平台 Manifest 或受控适配器中。

同一产品家族下的文生、图生、首尾帧、多图参考、视频编辑或音频参考等能力必须登记为独立任务变体。节点显示家族名称和当前支持的操作；运行前由输入类型、角色、数量和参数条件解析唯一变体。无法唯一解析时要求用户选择，不得静默切换到另一个变体。

### 5.5 Agent 的安全输出和交付边界

本地 Agent 的工作结果分为“草稿”和“可启用版本”两层：

1. Agent 可以生成 Manifest、能力档案、适配器代码、目录解析夹具、请求快照和本地契约测试，但这些内容默认是草稿。
2. 项目必须执行 JSON Schema、语义引用、模型唯一性、证据等级、允许域名、脱敏字段和静态请求快照校验；所有校验通过后才可标记 `contract_validated`。
3. 没有真实生成授权时，禁止上传素材、提交任务、轮询任务、下载结果或标记 `runtime_verified`。地址验证和模型目录拉取不等于生成验证。
4. Agent 不得读取、输出或写入 API Key、Cookie、完整 Authorization、签名 URL、本机绝对路径和用户素材正文。凭据只由用户回到 API 设置后填写。
5. 适配器只允许修改当前自定义平台的受控文件和测试；不得新增私有画布节点、修改公共连接语义、把第三方字段散落到节点前端，或覆盖官方平台档案。

Agent 完成后必须报告：改动文件、官方证据来源、模型家族与任务变体、字段映射、仍为 `unknown/needs_profile` 的能力、dry-run 结果、当前用户启用清单、规范差异，以及明确未执行的真实付费操作。

### 5.6 用户模型启用投影

模型生命周期固定为四层：

```text
第三方目录
→ 当前用户目录快照
→ 当前用户按四类选择的启用清单
→ 能力档案、受控适配器和 readiness=ready 的画布候选
```

用户可以先拉取完整目录，再在文本、图片、视频、音频分类中取消不需要的模型。取消或删除只停用当前用户的画布投影：它不会删除平台适配、能力档案、Manifest 或历史画布；它也不会影响其他用户。模型重新需要时，可以从当前目录再次启用。

画布候选必须同时满足“当前用户已启用、模型家族/任务变体已登记、当前输入组合匹配、能力档案有效、适配器就绪”。历史节点保留原始模型 ID 和能力快照；如果模型后来被停用或档案失效，再次运行时必须明确阻止并要求重新选择，不能悄悄替换成同名或相近模型。

### 5.7 初版规范的校准方式

这份规范是可执行初版，不是一次性冻结的最终协议。官方平台和自定义平台应按同一工作表至少完成一次本地目录解析、标准请求构造、平台请求快照和参数展示对照。实际接入中出现规范无法表达的字段、任务状态、上传方式或错误语义时，按以下顺序处理：

```text
记录官方证据和差异
→ 先判断能否用现有标准语义表达
→ 必要时扩展能力词典、Manifest Schema 或标准请求
→ 再修改平台适配器和测试
→ 更新本规范的版本与验收项
```

不能为了让某个平台通过而把平台特例硬编码进画布，也不能把一次 dry-run 通过误写成所有同类模型已经真实可用。规范、能力档案和适配器都应保留版本；历史运行使用提交时快照，不被后续规范修订重新解释。

## 6. 统一输入和任务语义

首批节点类型：

- `text_generation`
- `image_generation`
- `video_generation`
- `audio_generation`

常用输入角色：`prompt`、`system_prompt`、`reference`、`first_frame`、`last_frame`、`source_video`、`reference_audio`、`mask`。

输入角色必须来自官方 Schema、官方文档或现有经过验证的适配器。不能仅凭模型名称推断首帧、尾帧或多图上限。

## 7. 静态验证，不产生费用

接入阶段使用 dry-run：

```text
选定平台、家族和输入组合
→ 解析唯一任务变体
→ 校验输入数量和参数
→ 生成标准请求
→ 映射为平台请求快照
→ 到此停止，不发送网络请求
```

dry-run 通过只能标记为 `contract_validated`。只有用户明确授权真实生成并且结果成功落地后，才能标记 `runtime_verified`。本项目当前验收禁止提交付费生成任务。

## 8. 交给 Codex 的指令模板

将下面指令、第三方官方 API 文档地址和项目本地路径一起交给 Codex：

```text
请在当前智能画布项目中接入一个新的第三方 API 平台。

第三方官方 API 文档：<在这里填写文档 URL 或本地文档路径>
目标平台名称：<平台名称>
项目接入规范：docs/第三方API平台接入规范.md
Manifest Schema：data/model_capabilities/provider-manifest.schema.json

执行要求：
1. 先阅读 AGENTS.md、接入规范、PRD 第四章和现有平台适配代码，不要从零另建画布节点。
2. 区分目录发现、用户启用、能力证据、运行准备度和真实运行验证。
3. 创建并校验该平台的 Provider Manifest；按模型家族和任务变体登记输入、参数、输出、endpoint 与证据。
4. 将平台配置接入 API 设置，使用户可以保存 Key、拉取模型、选择或删除启用模型。
5. 画布只显示 API 设置中仍启用且 readiness=ready 的模型；删除模型后不得继续出现在新建节点中。
6. 复用标准请求和现有平台适配器边界；必要时新增受控适配器，不得在 Manifest 中执行任意代码。
7. 为文本、图片、视频、音频中平台真实支持的节点补齐动态参数和输入筛选。
8. 编写目录解析、家族路由、参数映射、后端校验和请求快照测试。
9. 只运行 dry-run 和本地测试，禁止提交任何真实生成任务或产生费用。
10. 文档没有说明的能力标为 unknown/needs_profile，不得凭经验猜测。

完成后报告：改动文件、支持的模型家族和变体、仍待补证据的模型、dry-run 测试结果、未进行的真实付费测试。
```

API 设置中的“复制 Agent 指令”会自动填入当前平台名称和 Base URL。使用时只需要把第三方官方 API 文档地址补到指令中，再把本项目复制出来的指令、本文档和官方文档一起交给本地 Agent；不要把 API Key 放进指令、Manifest、能力档案、画布导出或日志。

### 8.1 交给 Agent 的输入包与交付结果

一次接入只需要把以下输入交给本地 Agent：

1. 当前项目根目录，以及项目内的 `AGENTS.md`、本规范和 Manifest Schema 路径。
2. 第三方官方 API 文档，至少覆盖认证、模型目录、各生成任务的提交字段、异步查询、取消、结果和错误码；缺少的文档要在交付报告中明确列出。
3. 平台名称、稳定平台 ID 和公开 Base URL。API Key、Cookie、Authorization、签名 URL 和用户素材不属于输入包。
4. API 设置中“复制 Agent 指令”生成的任务文本；该指令会自动带入当前平台名称和 Base URL，并跟随当前界面语言生成中文或英文版本。

Agent 完成后必须交付一份可审查结果，而不是只说“已经接好”：

- Provider Manifest、能力档案、受控适配器和契约测试的文件清单。
- 官方字段到标准字段的映射工作表，以及模型家族、任务变体和真实 `model_id` 路由。
- 已通过的 Schema、语义、安全、dry-run 和请求快照测试；dry-run 必须明确返回 `network_requested=false`。
- 当前可标记为 `ready` 的模型、仍为 `unknown/needs_profile/adapter_missing` 的模型及原因。
- 规范无法表达的真实平台差异，以及建议先修改公共标准还是仅修改平台适配器。
- 明确声明没有执行真实上传、生成提交、任务轮询、结果下载或任何可能计费的操作。

用户检查交付结果后，再回到 API 设置填写 Key、拉取目录并选择启用模型。Agent 适配完成不代表目录中的全部模型自动启用；目录、用户启用清单和画布可运行候选仍然是三个独立层级。

### 8.2 API 设置中的用户提示

自定义平台入口应持续显示以下事实：

> 自定义平台需要先完成一次本地适配：把第三方官方 API 文档、本项目接入规范和 Manifest Schema 一起交给本地 Agent（例如 Codex）。Agent 会在不改变画布节点稳定语义的前提下，生成平台 Manifest、能力档案、受控适配器和 dry-run 测试。适配完成后再回到这里填写 Key、拉取模型，并按文本/图片/视频/音频选择要启用的模型。拉取目录不会自动开放模型；删除模型只会从当前用户的画布候选和真实请求中移除，不会删除平台适配、能力档案或历史画布。禁止把 API Key 放进 Agent 指令、文档、Manifest、画布导出或日志。

页面上的“查看规范”应指向 `/api/provider-integration-guide`，用于人类阅读；“查看 Schema”应指向 `/api/provider-manifest-schema`，用于 Agent 或程序读取；“复制 Agent 指令”只复制不含密钥的任务模板。页面同时应说明：规范文件为 `docs/第三方API平台接入规范.md`，Schema 文件为 `data/model_capabilities/provider-manifest.schema.json`；用户可以把这两个项目内路径和第三方官方 API 文档一起交给本地 Codex。模型目录、已启用模型和 Key 都是当前用户配置，不会因为某个用户拉取过模型就自动共享给其他用户。

## 9. 验收清单

- API 设置可以新增、保存、删除平台。
- Key 不进入 Manifest、能力档案、画布和日志。
- 模型目录可以拉取，用户可以按四类启用或删除模型。
- 拉取模型和启用模型是两个动作：未点击“应用到模型列表”前，目录中的新模型不会进入画布；删除后立即退出新建节点候选。
- 未启用模型不进入画布；未适配模型显示明确原因，不可运行。
- 同一家族的多个变体不会平铺成重复产品名称。
- 输入变化能够筛选模型，并解析到唯一真实变体。
- 动态参数只显示官方确认字段。
- 前后端使用同一能力档案校验。
- dry-run 生成标准请求和平台请求快照，`network_requested=false`。
- macOS 和 Windows 路径、脚本和 CLI 差异已检查。

## 10. 迭代规则

本规范是初版，不假设一次完成。每接入一个官方平台或第三方平台，都要记录规范无法表达的真实差异；优先扩展统一语义和 Schema，避免把平台特例硬编码进画布。用户对参数、命名和展示方式的反馈应同步回写本规范、能力档案维护规范和对应测试。理论规范必须通过至少一个已配置平台的本地 dry-run 对照后再升级为稳定规则；真实生成和付费验证另行授权。
