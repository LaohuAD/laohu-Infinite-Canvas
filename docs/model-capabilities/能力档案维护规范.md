# 能力档案维护规范

## 1. 先区分事实和工具

能力档案只登记模型接口真实要求和真实支持的字段，不把所有可能有用的画布工具都写成模型能力。

| 层级 | 记录内容 | 例子 |
| --- | --- | --- |
| 模型必填输入 | 缺少就不能调用的输入 | `prompt`、首帧图片、待处理视频 |
| 模型可选参数 | 接口明确支持的普通参数 | 比例、分辨率、时长、输出数量 |
| 模型高级参数 | 接口明确支持但低频使用的参数 | `seed`、负面提示词 |
| 素材处理 | 画布在调用前后处理素材 | 裁剪、缩放、遮罩、抽音频 |
| 效率工具 | 帮用户准备或编排输入 | Skill、提示词模板、提示词优化、循环 |
| 平台内部字段 | 请求认证和任务协议字段 | 上传地址、任务 ID、轮询状态 |

素材处理、效率工具和平台内部字段不得混入模型参数表单。只有接口证实接受 `mask` 时，画布制作的遮罩才可以作为模型输入角色提交；`seed` 也只有在当前模型档案确认支持时，才进入高级参数。

## 2. 能力证据等级

从强到弱依次为：

1. `runtime_verified`：当前项目请求和测试证明字段确实参与调用。
2. `official_schema`：平台官方提供机器可读 Schema 或注册表。
3. `official_documented`：官方文档明确写出字段、范围或依赖。
4. `model_card_only`：模型卡只描述方向，没有证明当前接口字段。
5. `unknown`：只有模型名称、分类或用户口述。

只有前三级可以自动生成可运行控件。后两级可以显示调查状态，但必须进入“待确认”，不能参与自动兼容筛选。

## 3. 档案更新流程

```text
保存平台全量模型目录快照
→ 查官方 Schema、官方文档和当前项目适配器
→ 按统一语义登记输入、参数、输出和映射
→ 填写证据、来源、核对日期和版本
→ 运行 JSON 格式校验和请求映射测试
→ 更新平台档案与总索引
→ 独立审计平台全量模型覆盖率
→ 最后按用户启用清单投影到画布
```

不得只凭模型名称、模型类别、同类模型经验或截图推断参数。官方文档改变时，先保留旧版本快照，再增加新版本；模型下线时标记 `deprecated`，不能直接删除仍被历史画布引用的档案。

## 4. 档案字段约束

- `provider_id`、`model_id`、`node_type`、`operation` 唯一确定一条能力记录。
- `family_id` 表示用户可见的产品模型家族；文生、图生、首尾帧、多参考和编辑等真实接口继续分别保存为任务变体。节点主要展示家族名，运行记录必须冻结实际 `model_id`、`operation` 和 endpoint。
- `inputs` 描述输入媒体类型、角色、最小数量、最大数量和互斥关系；官方接口明确限制素材规格时，还要登记对应的字符数、文件大小、像素或时长约束。
- `parameters` 只描述模型接口参数，必须写类型、默认值、枚举或范围和显示依赖。
- `request_mapping` 把统一语义映射到平台字段；没有映射证据的字段不得填写。
- `output` 描述输出媒体类型、数量范围和异步特征。
- `evidence` 必须包含等级、来源、核对日期和备注。
- 档案事实 `status` 使用 `confirmed`、`pending`、`deprecated`，未知能力不得写成 `confirmed`。
- 运行准备度使用独立字段，取值为 `ready`、`needs_profile`、`adapter_missing`、`deprecated`；它不能覆盖档案事实状态。

参数不适用时，前端可以保留用户草稿，但后端不得提交；输入或参数无法满足档案约束时，运行必须被阻止并说明具体缺口。

输入规格统一使用以下字段，单位不可混用：

| 字段 | 含义 | 单位 |
| --- | --- | --- |
| `min_chars` / `max_chars` | 单段文本字符数 | Unicode 字符 |
| `min_bytes` / `max_bytes` | 单个文件大小 | 字节 |
| `min_width` / `max_width` | 图片或视频宽度 | 像素 |
| `min_height` / `max_height` | 图片或视频高度 | 像素 |
| `min_pixels` / `max_pixels` | 单个画面总像素 | 像素 |
| `max_aspect_ratio` | 长边与短边最大比值 | `N:1` 中的 `N` |
| `min_duration_seconds` / `max_duration_seconds` | 单段视频或音频时长 | 秒 |
| `max_total_duration_seconds` | 同一输入角色全部媒体总时长 | 秒 |

点击运行后，画布必须在创建结果占位和请求第三方接口之前执行预检。后端优先读取本地素材文件的真实大小、像素和媒体时长；远程素材可以使用浏览器已读取的元数据，但只要档案声明了约束而对应数据无法读取，就必须阻止运行并提示用户重新上传，不能跳过检查后等待上游报错。没有官方 Schema、官方文档或当前适配器证据时，不得凭同类模型经验补规格限制。

模型目录同步只负责发现候选模型。目录中的媒体分类、名称后缀和模型卡不能直接生成 `confirmed` 档案；必须先校正输出类型、归并模型家族、建立任务变体，再核对官方 Schema 或文档和平台适配器。缺少能力证据时，事实状态为 `pending`、运行准备度为 `needs_profile`；已有确认档案但适配器未支持时，事实状态可以是 `confirmed`，但运行准备度必须是 `adapter_missing`。两种情况都不得进入节点可运行列表。

平台全量目录和用户启用清单是两份不同数据。全量目录回答“平台 A/B/C/D 中哪些已经适配”，用户启用清单回答“当前用户希望在画布看到并调用哪些模型”。即使用户只启用 A、B，覆盖审计仍必须检查 C、D；即使 C、D 已完全适配，只要用户未启用，它们就不得出现在画布模型候选或真实请求中。

当需求范围写“全部平台”或“所有正式平台”时，先从 API 设置和注册表生成平台核对表，再分别审计 RunningHub、AI MONEY、ModelScope、即梦 CLI、GPT CLI 以及未被用户明确排除的其他正式平台。不得用某两个平台的完成度代表全局完成度；每个平台都要报告目录总数、可运行数、待补 Schema 和适配器缺口。只有用户明确说“暂时不处理”的平台才允许在本轮排除，并在报告中保留排除原因。

任务变体按以下顺序选择：用户显式操作模式、输入媒体角色与数量、家族支持范围、参数依赖、当前平台生效站点和适配器状态。存在多个候选时要求用户选择，不能仅按连线顺序、模型后缀或同类模型经验静默猜测。

## 5. 版本和快照

能力档案的 `version` 是接口事实版本，不等于应用版本。修改输入角色、数量、参数范围、字段映射或输出结构时递增版本。运行记录至少保存平台、模型、档案版本、标准参数、输入素材 ID、Skill 快照和原始请求追踪 ID。

## 6. 双平台与路径规则

能力档案使用 UTF-8 JSON 和项目相对路径，不写入 macOS 的 `/Users/...` 或 Windows 的盘符路径。程序通过 `pathlib` 或等价的跨平台路径 API 读取档案；平台 URL、模型 ID 和请求字段保持官方原文，不做本地化翻译。

## 7. 密钥与隐私

能力档案严禁出现 API Key、Authorization 值、Cookie、上传文件绝对路径和用户素材内容。密钥继续由 `API/` 管理，用户模型启用状态和地址继续由 `data/api_providers.json` 管理，测试日志不得打印完整密钥。
