# 模型能力档案

这里维护智能画布运行节点所依赖的模型接口能力、参数语义和平台字段映射。

## 目录职责

| 内容 | 文件位置 | 变化频率 | 使用者 |
| --- | --- | --- | --- |
| 能力语义、字段分层和档案格式 | `data/model_capabilities/capability-vocabulary.json`、`能力档案维护规范.md` | 低 | 前端、后端、维护者 |
| 平台和模型能力事实 | `data/model_capabilities/providers/` | 中高 | 前端筛选器、后端校验器、维护者 |
| 所有档案的入口和状态 | `data/model_capabilities/registry.json` | 中 | 程序、迁移工具、维护者 |
| 用户启用模型、地址、协议和密钥状态 | `data/api_providers.json`、`API/` | 高频 | API 设置、后端 |

模型能力档案不是 API Key，也不是用户的模型启用列表。`data/api_providers.json` 继续保存用户实际添加或启用的模型；本目录只描述模型在什么条件下能接收什么输入、支持什么参数，以及如何转换成平台请求。

## 当前读取约定

程序读取顺序固定为：

```text
档案索引 → 平台档案 → 能力语义词典
```

然后再与 `data/api_providers.json` 中用户启用的平台和模型求交集。没有能力档案或证据不足的模型，只能显示“待确认”，不能自动生成可运行参数，也不能静默丢弃用户选择的参数。

## 文件状态

- `stable`：字段语义和文件格式，除非架构变化，否则不频繁修改。
- `maintained`：平台档案，跟随官方接口和项目适配器更新。
- `pending`：已经出现在配置或官方目录中，但当前证据还不足以开放完整运行能力。
- `deprecated`：平台或模型已下线，只用于历史记录和迁移，不参与新运行。

## 维护入口

- 修改字段含义、证据等级或档案格式：先看 `能力档案维护规范.md`，再改 `data/model_capabilities/capability-vocabulary.json`。
- 平台接口字段、异步流程或响应路径变化：改 `平台适配说明.md` 和对应平台档案。
- 具体模型新增、下线或能力变化：只改对应的 `providers/*.json`，并同步 `registry.json`。
- 用户 API Key、模型启用状态或自定义模型：改 API 设置产生的 `data/api_providers.json`，不要写入能力档案。

所有变更都必须记录来源、核对日期、证据等级和档案版本。历史运行使用保存时的能力档案快照，不因档案后续更新而改变解释。
