## 方案与边界

只隐藏旧结果卡容易留下断链；完全替换平台执行扩大回归风险；本轮采用独立创作状态模块与一次性迁移，复用能力档案、预检、执行适配、素材存储和预览。节点上方预览结果，选中后下方编辑参数；任务独立保存，失败/取消保留旧结果。

node.id 是布局身份，creationId 是共用创作关联，resultId/materialId 是已有文件索引。参数或提示词改变时分支；原节点重新运行持续同步共用副本，副本单独运行才分支（creationOwnerNodeId 记录方向）。Agent 按节点修订号校验写回，避免覆盖手改。

旧执行节点吸收结果版本，下游连线映射并锁定原版本。上传素材保持纯素材；生成素材导入恢复有证据的参数。影院流程复用文本、图片、视频节点及明确关系，专业推理由外部 AI 视觉完成。

## 创作说明的最新约定

2026-09-12 用户进一步确认：说明是每段的创作备忘和上下文锚点，只使用一个自由 Markdown 文本区，不限制固定格式、必填字段或分段时长。Agent 接续第 100 段时，可以按节点 ID 读取该段正文、完整说明和真实引用，恢复已确定的结论再创作资产与视频提示词；不依赖重新塞入全部聊天记录。可建议记录讲戏、资产状态、衔接和来源，但不做填空任务。旧说明完整转成文本；本约定取代早期表格式说明。

## 四个工作区

### 剧本

- 完整剧本是主要编辑内容，允许用户手写、粘贴或由外部 Agent 填写，用户可编辑确认。
- 从完整剧本派生集数、场次及导航，不能把多个互相冲突的小稿当成真源。
- 剧本正文、背景与人物介绍、格式和符号说明分区呈现。
- 剧本格式和专业创作约束遵循 AI 视觉当前规则；保留原始输出及来源，结构化展示不另造创作规则。

### 分段

- 先剧本，后分段，再汇总资产。每段对应一条待生成视频，计划时长 4–30 秒；这不代表每个视频模型都支持全部时长，执行仍按模型能力校验。
- 左侧可滚动表格/列表，右侧当前段详情，各自滚动，不采用长列表底部详情的上下布局。
- 每段有稳定编号及内部 ID、原剧本定位和文本、预估时长、本段作用、讲戏说明、需要的资产及其用途/状态、开始状态、结束状态。
- 开始状态说明新开场或如何承接上一段；结束状态说明镜头和转场是否为下一段准备。保留有用的衔接信息，不添加重复的“接续提醒”“中间段变化”栏。
- 段内镜头与视频段是不同层级，不能把一个镜头机械等同于一条视频。
- 此处决定需要制作哪些资产；资产生成后再回填可用引用。不要给尚不存在的素材伪造已完成引用。
- 修改通过手工编辑或外部 Agent 定位到该段，不堆放“重新分析”“生成视频提示词”等重复创作按钮，不额外增加无用状态列。

### 资产

- 导航按人物资产、场景资产两大维度组织；人物下再按名称展开素体、服装、妆造、群像、专属道具等；场景对应剧本场次，组织场景视图、俯视图、多视图、道具、风格等。
- 只制作需要复用、保持形象一致或明确参考的资产，避免每个瞬时动作都新建资产。
- 人物、服装、道具和场景均可有状态变体，例如完好/破损、整洁/受伤。区分基础资产、状态变体与同一资产的多次生成版本。
- 表格展示名称、归属和类别、状态、用途、使用它的段落、参考资产、可编辑生图提示词、生成结果与选定版本。
- 资产间也支持 `@引用`，例如人物着装、道具或场景融合；引用具有缩略图和悬停大图。
- 可逐个生成，也可多选后批量生成。素材和生成图片保存在资产工作区并复用素材库的稳定引用。
- 显示名称使用有意义的中文及 `_`，例如 `林澈_素体_正常`、`林澈_外套_破损`。内部稳定 ID 不代替显示名称；重命名、重新排序不能破坏关联。

### 视频

- 菜单名称为“视频”。按分段编号展示，每行/卡片对应一段，关联同一个分段对象。
- 显示该段资产引用、可编辑三段式提示词、生成参数和视频结果/版本。三段式遵循 AI 视觉能力约定，包含基础设定、氛围与画质、画面内容。
- 提示词中的 `@引用` 与资产工作区使用同一引用体系，提供缩略图和悬停预览。
- 从上一段成片抽帧或截取片段，作为下一段参考；派生素材必须真实存在、保留来源与时间范围，不能覆盖原视频。
- 状态资产生成、成片抽帧、成片片段参考属于不同来源方式，应能识别和追溯。不要默认用上一段尾帧而忽略实际画面是否符合下一段要求。

## 外部 Agent 接入与一致性

现有 Agent 接口主要通过打开的画布执行命令；不能宣称已经支持关闭浏览器后的无人值守执行。影院需要在现有接口之上补充作品、剧本、分段、资产关联和视频记录能力，不能只新增一个展示页面。

用户选中整行时，外部 Agent 获得该对象上下文；选中单元格时，获得明确字段范围。连接说明或上下文接口需携带作品 ID、工作区、对象 ID、字段和内容版本。创作对话在外部 Agent 持续进行，影院保存结果、引用和变更，不重新引入内置 Skill 创作系统。

用户手改后 Agent 必须重新读取最新内容；写回需检查版本，不能覆盖用户刚改的正文。原始创作输出与结构化展示应能追溯，但不能维护两份互相冲突的剧本。资产、画布节点与影院记录通过稳定 ID 关联，复用同一素材文件，避免两套重复库。

各步骤可以单独使用，也可以承接上一步。独立使用时应明确缺失依赖，不能要求用户为单张写真先写完整剧本。写真、风格图片和单独资产创作保留为资产区的可用情境，不扩张成重复页面。

所有交互复用现有画布与素材库的组件：参数选择、滑块和数字输入、批量选择、媒体预览、运行反馈、命名与确认弹窗。视觉简约、按钮紧凑，操作有效；不用示例假按钮充当已实现功能。

### 生成中动效与画布重绘（2026-09-13）

用户反馈：混色模糊背景不够干净，点选、拖动等操作会让生成动画从头播放，希望位置自然随机变化。

现状依据：`render()` 替换节点 DOM，旧 `.creation-running-light` 通过 CSS 周期动画播放，新 DOM 每次从零开始。保守调整颜色或延迟只能掩盖重启动作；完全替换画布渲染器范围过大。本轮选择局部重构：`CanvasNodeView.syncRunningEffects` 用节点 ID 与任务 ID 持有动效 DOM 和 Web Animations 实例，渲染后重新挂载原实例。随机轨迹按任务种子生成，使用 transform 与 opacity，不增加逐帧画布重绘和外部依赖。任务首次显示按真实开始时间衔接，终态和删除释放实例。

呈现统一为中性表面、三组轻微柔光与细光点；新任务不透出画布网格，重跑保留压暗的旧媒体。时间和取消仍由原任务系统控制，不显示虚构百分比。系统减少动态效果时保留静态状态，恢复后从原位置继续。模型调用、素材文件和任务记录格式保持不变，无数据迁移。视觉参考：https://magicui.design/docs/components/backlight （仅参考局部光效，未引入组件依赖）。

验收覆盖真实点选、拖动、滚轮缩放、连续重绘和改尺寸前后的同一动画实例/时间，随机轨迹差异、长时间播放、明暗主题、窄窗口、减少动态效果及取消释放。
