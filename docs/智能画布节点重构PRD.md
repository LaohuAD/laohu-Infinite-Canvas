## 一、改造目标

当前智能画布把素材展示、提示词编辑、模型选择、生成参数、运行状态和生成结果集中在少数节点中。短期操作方便，但随着文本、图片、视频、音频和 RunningHub AI 应用能力增加，节点职责开始混杂，模型参数也难以精确适配。

本次改造不是重新制作一套空白画布，也不是重构所有智能画布节点，而是只重构现有 `smart-image` 上传/混合节点中的职责：

1. 将纯素材上传和生成结果统一为一个素材节点，只通过来源状态区分用户上传和模型生成。
2. 将 `smart-image` 中的图片、视频、音频和 AI 应用能力拆成运行节点，将音乐生成从音频生成中独立拆出，并将文本生成从历史 `smart-prompt` 入口拆为独立的 `smart-text-generator` 节点。
3. 根据平台、模型能力和实际连接的输入素材，动态筛选模型并展示参数。
4. 让现有循环节点在不改变本体的前提下能够驱动六类新运行节点，批量产生独立结果。
5. `smart-prompt`、`smart-loop`、`smart-group`、`smart-minimax` 等历史节点保持兼容；新建文本生成使用 `smart-text-generator`，旧 `smart-prompt` 只作为历史画布兼容入口保留。
6. 让画布只保存引用关系，素材文件和生成结果继续由素材库统一管理，避免重复复制和空间膨胀。

### 1.2 重构路线比较

**方案 A：继续扩展现有混合节点**

- 做法：保留 `smart-image` 为主节点，只增加更多模式、模型参数和结果展示。
- 优点：短期代码改动较少，旧画布天然兼容。
- 问题：输入、运行和结果继续耦合，循环、模型筛选和多媒体结果会越来越难维护。
- 结论：只适合临时补丁，不适合作为本次长期方案。

**方案 B：迁移层重构，推荐**

- 做法：先抽出统一素材引用、模型能力、执行、结果和连接契约；迁移器读取旧节点并生成新节点，迁移成功后旧节点退出正常运行体系。
- 优点：最大限度复用现有执行、恢复、预览、循环和专用工具，同时保证最终画布结构干净，只保留新节点。
- 代价：实施阶段需要维护旧数据迁移器和新节点，必须建立清晰迁移边界，但不需要长期维护两套运行节点。
- 结论：在数据安全、开发风险和长期结构之间最平衡，作为本 PRD 的实施路线。

**方案 C：完全重写智能画布**

- 做法：建立全新节点引擎和数据结构，再一次性导入旧数据。
- 优点：理论上结构最整齐。
- 问题：现有近两万行交互和执行逻辑中有大量边缘处理，完全重写很容易丢失任务恢复、分组连线、编辑工具和 MiniMax 时间线等已验证能力。
- 结论：当前不采用；只有现有引擎已经无法承载类型化端口时，才单独论证底层画布引擎替换。

## 二、硬性产品原则

### 2.1 拆分结构，不丢失能力

本次重构必须先建立现有智能画布能力清单，再逐项迁移。原有能力如果同时被多个新节点使用，应下沉为公共能力，而不是复制多份或只保留在其中一个节点。

需要保留并重新归属的能力至少包括：

- 拖拽、点击、粘贴和素材库导入。
- 素材预览、播放、展开、编辑、收藏和删除关系。
- 提示词输入、模板、LLM 生成或优化、系统提示词。
- 平台和模型选择、尺寸、比例、分辨率、质量、数量及模型专属参数。
- 远程 API 与本地 CLI 的统一平台选择、安装检测、登录状态、版本检查和任务恢复。
- 图片参考、多图参考、首帧、尾帧、视频参考、音频参考和多模态输入。
- RunningHub 模型 API和 AI 应用的动态字段映射；旧工作流映射只服务历史画布和既有专用节点兼容。
- 任务提交、轮询、恢复、错误提示、运行状态和生成日志。
- 结果预览、历史回溯、再次作为输入和素材库持久化。
- 循环、串行、并发、批次、可变提示词和轮次编号。
- 画布连线、自动连接、分组、撤销、复制、粘贴和保存。

### 2.2 节点职责单一

新版节点分为四层：

```text
素材节点 → 运行节点 → 素材节点（`result` 状态）
                ↑
             循环节点
```

- 素材节点：只引用并提供文本、图片、视频或音频媒体，输入素材和生成结果使用不同来源状态；上传素材与生成结果不是两种底层节点。
- 运行节点：只负责配置模型、接收输入并执行任务。
- `result` 状态：表示素材节点来自某次运行的持久化结果；结果可以独立保存，但不因此创建另一种节点类型。
- 循环节点：只负责编排运行次数、批次、提示词变量和串并行策略。

### 2.3 结果独立持久化

- 运行节点与素材节点分开；素材节点通过来源状态承载上传素材或生成结果。
- 每次运行产生新的运行记录；运行返回的每一项媒体分别产生独立结果记录，不覆盖旧结果。
- 同一次运行返回多个同类型结果时，画布默认使用一个处于 `result` 状态的素材节点集中展示，但节点内部保存独立的 `result_ids`，每一项都能单独预览、连接、下载、删除或提取。
- 同一次运行返回不同媒体类型时，按媒体类型创建多个素材节点，再由组合结果组统一引用。
- 删除运行节点或画布，只删除画布工作流关系，不删除已经保存的生成结果。
- 生成结果只有在用户从素材库中明确删除时才删除。
- 运行节点的双击窗口可以预览最近一次结果和历史记录；结果本体由素材节点承载，不另造第二种媒体节点类型。

### 2.4 画布引用素材，不复制素材

- 本地拖拽、点击上传或粘贴到画布的文件，默认进入素材库的“临时素材”。
- 从“资产素材”“临时素材”或“生成结果”拖入画布时，只创建引用节点，不复制文件。
- 引用节点保存稳定素材 ID 和读取地址，不依赖容易失效的磁盘绝对路径。
- 相同内容继续使用 SHA-256 去重；重复导入不得产生第二份文件。
- 临时素材收藏或晋升为资产素材时，移动归类并保留稳定引用，不复制第二份。

### 2.5 运行、结果、文件和画布引用必须分层

运行任务、逻辑结果、物理文件和画布节点不是同一个对象，必须使用不同稳定 ID：

| 层级 | 稳定标识 | 含义 | 删除或去重规则 |
| --- | --- | --- | --- |
| 运行记录 | `run_id` | 用户点击一次运行或循环中的某一轮执行 | 保留输入、参数、状态和追踪信息；删除画布不删除运行记录 |
| 运行尝试 | `attempt_id` | 同一运行的首次提交或某次明确重试 | 用于区分恢复原任务和发起新计费任务 |
| 结果项 | `result_id` | 某次运行返回的一项文本、图片、视频或音频 | 每项独立追溯、连接和删除；内容相同也不能合并运行语义 |
| 物理内容 | `blob_id` 或内容哈希 | 磁盘中实际保存的一份文件或文本内容 | 相同 SHA-256 可以复用同一物理内容，引用归零后才能物理清理 |
| 画布节点 | `node_id` | 画布上的素材节点或运行节点 | 删除只影响画布结构，不删除结果和物理文件 |
| 结果组 | `group_id` | 多轮或多媒体结果的结构化引用集合 | 删除组只删除组织关系，不删除组内结果 |

输入素材继续使用现有稳定素材 ID；生成结果使用 `result_id`，并通过物理内容引用指向本地文件。一个素材节点可以保存一个或多个同媒体类型的 `result_id`，但不能把多个结果压成一条无法拆分的记录。

物理去重只减少磁盘副本，不改变业务记录。例如两次运行生成完全相同的图片，可以共用一份物理文件，但仍保留两个 `result_id`、两个来源运行和两套参数快照。删除其中一个结果不能让另一个结果失效。

## 三、节点体系

### 3.1 添加节点窗口

双击画布空白区域后打开“添加节点”窗口。第一阶段包含：

**添加资源**

- 素材

**常规节点**

- 文本生成：创建 `smart-text-generator` 节点。
- 图片生成
- 视频生成
- 音频生成

**ComfyUI 节点**

- `RunningHub ComfyUI`：只调用已在 API 设置中配置好的 RunningHub AI 应用。
- 本地 ComfyUI：调用本机自定义工作流。

**工具节点**

- 循环
- MiniMax

窗口使用紧凑纵向图标列表，按以上四类从上到下排列，不使用大卡片宫格。分组不出现在添加节点窗口中，因为它是对现有节点的组织操作，不是独立运行节点；用户框选节点后通过分组快捷键或明确分组命令创建。结果组由运行和循环结果自动产生，也不作为普通手动创建入口。

连接线松到空白画布时复用同一套添加节点窗口，不再默认创建空素材。用户选择节点后，在连接线落点创建该节点，并自动完成来源节点到新节点的连接；关闭或取消窗口不创建节点、不写入连线。

按住 `Shift` 时，只要鼠标起点位于节点所属区域，就可以直接从该节点输出端拉线，不要求节点预先选中。起点判断在画布捕获阶段统一处理，节点内部按钮、输入框、开关、下拉框、文本框、浮动参数层都归属于节点；运行配置面板虽然是独立 DOM，也按当前配置节点归属处理。端口本身保留原有“从指定端口起线”的语义。若该节点属于当前多选集合，则从整个多选集合共同起线；否则只从鼠标所在节点起线。落到目标节点时，以上控件区域全部视为目标节点有效范围，不按鼠标位于节点左半边或右半边猜测端口；命中顺序必须优先采用事件实际所在控件或浮层声明的所属节点，再回退到屏幕元素堆栈和节点几何边界，防止浮层覆盖其他节点时误连到下层节点。落到空白处则打开上述创建菜单。鼠标位于空白画布时按住 `Shift` 拖动，继续执行现有断开连接线操作。

除 `smart-image` 外，原智能画布的其他节点全部保持现有节点类型和功能，不参与本次拆分。新节点需要连接这些节点时，通过端口或数据适配完成，不反向修改原节点的界面、参数和运行逻辑。

这里的“分组”和“结果组”不能混为一个节点：现有智能分组解决画布布局和连线整理；结果组解决稳定结果引用、整体输出和单项输出。两者可以复用容器视觉和拖拽能力，但数据契约和删除语义必须分开。

### 3.2 素材节点（上传状态与结果状态）

素材节点是本次重构中的单一媒体实体。它既可以承载用户上传或从素材库导入的输入，也可以承载图片、视频、音频或文本生成后的结果。用户感知上可以把前者称为“上传素材”、后者称为“生成结果”，但底层节点类型、引用方式和媒体工具保持一致。技术文档中如需说明旧称，可将“统一媒体节点”视为本节点的技术描述，不作为用户界面名称。

节点状态：

- `input`：用户上传、粘贴或从素材库拖入的素材。
- `result`：由提示词节点或六类新运行节点生成的结果。
- `reference`：从已有素材或结果提取出来，作为后续节点输入的引用。

状态只描述来源和运行关系，不复制文件。一个 `result` 素材节点可以直接连接到下游运行节点，作为图片、视频、音频或文本输入；也可以再次被收藏、下载、编辑或拖入素材库。

纯素材上传能力只负责接收、引用和展示文本、图片、视频、音频素材，不负责模型选择和生成任务。结果状态只增加来源运行信息，不改变媒体节点的预览、编辑和输入能力。

素材节点必须保留当前项目已经存在的媒体操作：

- 预览和大图查看。
- 下载单项、下载全部和新窗口查看。
- 收藏到资产素材，或保持临时素材状态。
- 图片裁剪、扩图、遮罩、画笔、宫格切分、宫格拼接和放大等已有工具。
- 视频和音频播放、暂停、进度控制及结果再次作为输入。
- 文本展开、复制原文和结果再次作为输入。
- 删除节点只删除画布引用；删除文件必须遵循素材库的明确删除规则。

用户从本地、素材库或已有结果记录拖入画布时，只创建素材节点引用，不复制底层文件。

支持的创建方式：

1. 拖拽本地文件到画布。
2. 点击上传并选择本地文件。
3. 使用 `Command/Ctrl + V` 粘贴。
4. 从右上角“素材库”面板拖入资产素材。
5. 从“素材库”面板拖入临时素材。
6. 从“素材库”面板拖入历史生成结果。
7. 将当前处于 `result` 状态的素材节点直接连接到下一个运行节点。

素材节点按实际内容展示文本、图片、视频或音频预览，但底层采用统一引用结构。节点标题和名称优先使用素材本身的用户可见名称，不用“图片”“视频”“音频”“文本”等类型词覆盖原名称；媒体类型由展示形态自然表达：图片显示图像，视频显示首帧和播放器，音频显示波形或播放条，文本显示正文或文本预览。

```json
{
  "asset_id": "稳定素材ID",
  "media_type": "text | image | video | audio",
  "source_scope": "asset | temporary | result",
  "url": "稳定读取地址",
  "name": "用户可见名称"
}
```

节点上的“收藏”操作将临时素材晋升为资产素材。操作成功后，节点继续引用同一个稳定素材 ID；生成结果也沿用同一稳定结果 ID。

### 3.3 文本生成节点（`smart-text-generator`）

文本生成节点是独立的文本运行节点，不等同于纯文本输入框。它可以使用文本、图片、视频和音频作为 User 输入，实际可用的输入组合由能力档案筛选：不支持当前输入类型或数量的模型不显示；能力已登记但适配器未完成的模型仍不可运行。

输入和发送顺序固定为：

1. 节点自身的用户指令，作为 User 内容的第一段。
2. 按输入连线创建顺序追加的文本素材内容。
3. 同一批输入连线中的图片、视频和音频，作为同一次多模态 User 消息的媒体内容发送。

节点自身的文本框优先级高于外部文本素材，但外部文本不会覆盖节点指令。每次运行保存输入类型、输入顺序、节点指令、系统提示词、Skill/模板快照、平台、模型和有效参数；生成结果创建新的文本素材节点，不覆盖任何输入素材。

节点设置包括平台、模型、可选系统提示词和用户指令。系统提示词可从提示词库或 Skill 库加载；Skill 内容在运行时保存快照。文本节点已经支持文本生成、文本优化、图片分析、视频分析和音频分析的统一请求构造与能力筛选，但音频理解只有在具体平台适配器完成后才能运行，不能因为请求对象存在 `audios` 字段就视为全链路完成。

### 3.4 图片生成节点（从 `smart-image` 拆出）

图片生成节点用于当前模型接口明确支持的文生图、图生图、图片编辑、多图参考等图片任务。扩图或放大如果由模型接口提供，则作为独立操作模式进入该节点；如果只是本地画布后处理，则保留在素材节点工具中。

现有基础：当前 `smart-image` 已经通过 `engine`、`apiKind`、`provider_id`、`model` 和 `runSettings` 支持多平台生成，并有独立图片编辑和后处理工具。新版先抽离配置与执行，再把编辑工具迁到素材节点的图片 `result` 状态，不重写已经验证的请求协议。

基础配置：

- 平台选择。
- 图片模型选择。
- 当前模型档案证实支持的操作标签，例如文生图、图生图、多图参考或图片编辑。
- 当前模型档案证实支持的必填输入、可选参数和高级参数；不得预设每个图片模型都有尺寸、比例、分辨率、质量或数量。
- 提示词输入。
- 独立于模型参数的“优化提示词”效率工具入口。

优化提示词支持：

- 选择 LLM 平台和模型。
- 选择系统提示词。
- 加载 Skill 作为系统能力。
- 选择提示词模板或填写自定义优化指令。
- 优化完成后由用户确认是否替换当前提示词。

输入和模型筛选：

- 只有文本输入时，只显示支持文生图的模型和操作。
- 连接一张图片时，只显示支持单图输入的图生图、编辑或参考能力；模型放大只在接口档案明确支持时出现。
- 连接多张图片时，只显示支持对应图片数量的模型和操作。
- 当前输入无法调用的模型不显示，避免让用户自行猜测。

输出：

- 每次运行生成独立图片结果记录，并由素材节点的图片 `result` 状态承载。
- 图片结果保存到素材库“生成结果 / 图片”。

### 3.5 视频生成节点（从 `smart-image` 拆出）

视频生成节点用于文生视频、首帧、首尾帧、多图参考、视频参考、音频参考、多模态生成、视频编辑和视频延长等任务。

现有基础：普通视频生成目前仍由混合图片节点切换 `apiKind=video` 承担，已有时长、比例、分辨率、音频、水印、固定镜头、首尾帧和多模态参数；`smart-minimax` 则是独立的时间线工作台。新版普通视频节点只迁移前者，MiniMax 节点不参与本次重构，不修改其界面、能力或数据结构。

基础配置：

- 平台选择。
- 视频模型选择。
- 能力标签，例如文生视频、首帧、首尾帧、多帧参考、视频参考、音频参考、全能参考、视频编辑、视频延长。
- 当前模型档案证实支持的必填输入、可选参数和高级参数；分辨率、时长、比例、质量、生成音频、水印或固定镜头都不能默认视为全部视频模型共有。
- 提示词，以及独立于目标视频模型参数的“优化提示词”效率工具入口。

输入和模型筛选：

- 只有文本时显示文生视频模型。
- 文本加一张图片时显示支持首帧或单图参考的模型。
- 文本加两张图片并映射为首帧、尾帧时显示首尾帧模型。
- 输入多张图片时显示支持对应数量和角色的多图参考模型。
- 同时输入图片、视频或音频时，只显示能够完整接收当前输入组合的多模态模型。
- 当前输入无法调用的模型不显示。

输入角色必须可见且可调整。系统可以按连接顺序提供默认映射，但用户可以将图片在“首帧、尾帧、参考图”等角色之间修改，也可以交换顺序。

输出：

- 每次运行生成独立视频结果记录，并由素材节点的视频 `result` 状态承载。
- 视频结果保存到素材库“生成结果 / 视频”。

### 3.6 音频生成节点（从 `smart-image` 拆出）

音频节点按操作能力划分，而不是把所有音频任务混为一个模式。

现有基础：项目已经能预览、传递和上传音频引用，RunningHub 与 ComfyUI 动态字段也能接收或返回音频；但没有统一音频模型配置和通用音频运行节点。因此本节属于在现有媒体管线上的新增能力，不应误写成已有音频生成逻辑的简单拆分。

首批规划能力：

- 文本转语音。
- 音色设计或声音设计。
- 口播、配音和音效生成。
- 后续根据平台能力增加语音转换、配音或其他音频操作。

基础配置：

- 操作类型。
- 平台选择。
- 音频模型选择。
- 当前模型档案证实支持的输入、语言、音色、格式、时长、采样率和其他参数；不把这些字段预设成所有音频模型共有。
- 文本、参考音频或其他模型要求的输入。

输出：

- 每次运行生成独立音频结果记录，并由素材节点的音频 `result` 状态承载。
- 音频结果保存到素材库“生成结果 / 音频”。

### 3.7 音乐生成节点（从音频生成中独立拆出）

音乐生成与音频生成都输出音频素材，但不是同一种模型能力。音频生成节点负责语音、口播、音色和音效；音乐生成节点负责歌曲、纯音乐、伴奏和配乐。两者必须拥有独立的平台筛选、模型家族、模型变体、参数能力档案和运行接口，不能因为输出类型同为 `audio` 就共用一套候选模型或参数表。

现状依据：当前能力档案已经将 Mureka、MiniMax Music 和 Suno 登记为 `music_generation`，将豆包 Seed Audio、Qwen TTS、MiniMax Speech 和 Voice Clone 登记为 `audio_generation`。本次拆分把已有分类落实到节点、预检和后端路由，而不是根据模型名称临时猜测。

基础配置：

- 固定输出类型为音频素材。
- 独立选择平台、模型家族和模型变体。
- 只显示当前音乐模型档案确认支持的文本、参考音频、歌词、风格、时长、数量和其他参数。
- 音乐模型未完成官方 Schema 或平台适配时显示为不可运行，不得回退到音频生成接口。

运行与迁移：

- 前端调用 `/api/canvas-music`，后端以 `music_generation` 完成能力预检，再进入对应平台适配器。
- 运行成功后新建独立音频素材结果；失败时不创建空结果节点。
- 旧音频节点若保存的是已确认的音乐模型，在加载画布时迁移为 `smart-music-generator`，保留平台、模型家族、模型和运行记录；无法确认音乐能力的旧值不静默迁移，要求用户重新选择。

### 3.8 RunningHub ComfyUI 节点（从 `smart-image` 拆出）

用户界面名称统一为 `RunningHub ComfyUI`。该节点只承载已在 API 设置中配置好的 RunningHub AI 应用，不承载 RunningHub 模型 API、RunningHub 工作流或本地 ComfyUI。RunningHub 模型 API 继续作为普通平台模型进入图片、视频或音频运行节点；本地 ComfyUI 使用独立的“本地 ComfyUI”节点。

现有基础：RunningHub 配置中已经能够保存 AI 应用字段，当前智能画布能够按字段类型渲染参数、分配媒体、上传输入并构建 `nodeInfoList`。新版重点是把这套逻辑从全局生成设置中抽成独立节点适配器，并补齐类型化端口、编号映射和组合结果，不是重新发明动态表单。

配置职责必须保持分离：API 设置保留 RunningHub Key、API 模型拉取以及多个 AI 应用的登记。用户只输入 AI 应用 ID 或 `/run/ai-app/...` 路径；系统调用官方详情接口自动同步标题、封面、说明、标签和完整字段 Schema，用户不能手工定义字段类型、名称、顺序、选项或封面。无效 ID 必须先验证失败并回滚，不能产生占位卡或污染配置。智能画布节点不重复输入 ID，只通过下拉框选择这些已同步应用。RunningHub 工作流不再提供新的添加、配置或选择入口；历史画布和 MiniMax 已有内部依赖只做兼容读取，不得重新暴露到新建界面，也不得因本次收敛被破坏性删除。

基础配置：

- 平台固定为 RunningHub，不显示重复的平台选择。
- 已配置 AI 应用选择。
- 从远端 Schema 或本地保存快照读取的完整参数列表。
- Key 计费来源选择；AI 应用已经确定的 24G/48G 等机器规格不在节点中重复显示或提交。

字段快照规则：

- 保存 `nodeId`、`fieldName`、字段类型、默认值、必填状态、顺序、数值范围、选项真实值、选项显示名称和媒体上传能力。
- `fieldData` 可能是 JSON 字符串而不是已解析数组，读取时必须结构化解析；字段以稳定键 `nodeId::fieldName` 对齐，不能用显示名称或数组位置猜测。
- 下拉或是否选项必须以官方显示名称呈现，以官方 `index/value` 作为真实提交值；不得把显示文案当成请求值。
- API 设置、画布节点、参数面板和运行提交共用同一字段解析语义。旧缓存缺少 `options`、`optionLabels` 或上传类型时，应从已脱敏的 `raw.nodeInfoList[].fieldData` 在内存中补齐，不要求重启服务或用户重新添加应用。
- 快照只保存允许的元数据和 Schema。官方响应中的示例 `curl`、API Key、令牌和未批准原始字段必须在后端脱敏后再返回和落库。
- 远端 Schema 变化沿用差异确认机制；未确认的新字段结构阻止运行，不静默沿用旧映射。`STRING/TEXT`、`SWITCH/SELECT`、`FLOAT/NUMBER` 等语义等价类型以及显式顺序 `0` 不得被误报为结构变化。

AI 应用参数面板使用一份统一的纵向字段清单。文本、图片、视频、音频等可由画布节点连接的输入字段也必须显示在这份清单中，不能把媒体输入隐藏到独立总入口，也不能与普通参数拆成两套顺序。参数行不显示“直接输入 / 外部节点”模式切换：字段没有外部连线时显示官方类型对应的原生控件；字段存在外部连线时自动显示已绑定素材或文本摘要。

字段展示顺序严格以 RunningHub 官方 `nodeInfoList` 返回的数组顺序为准。系统保存明确的 `schemaOrder`，不得再按文本、图片、视频、音频、开关或数字等字段类型重新分组排序；旧快照没有有效顺序信息时，以快照数组位置兼容迁移，不把全为 `0` 的旧排序误报为远端 Schema 变化。

参数面板只允许出现在节点右侧或下方：右侧空间充足时优先右侧，右侧不足时固定从节点下边界展开，禁止放到节点左侧。下方剩余高度不足时压缩参数清单的可视高度并启用内部纵向滚动，不能通过整体夹取让面板重新覆盖节点，也不能只裁掉后续参数。

每个媒体输入都使用官方字段名称，例如“数字人图片”“音频”“提示词控制”，不以“文本 1”“图片 1”等泛化编号作为主要标签。内部仍可按类型和顺序建立候选槽，但连接必须把稳定 `targetFieldKey` 写入连线。来源素材可以显示目标字段名称。`RunningHub ComfyUI` 节点保留原有图标、标题、平台信息、应用 ID、底部输入数量和参数入口状态；仅把卡片中部原字段明细区替换为当前 AI 应用名称，不再在中部重复列出输入槽位。保存、重开、复制、导入导出和运行提交都以连线字段键为事实来源，不能只把映射存在临时 UI 状态。

应用参数清单采用纵向单列卡片：每个字段的名称在上、控件在下，字段行由控件内容自然撑高且禁止压缩。长文本、媒体上传和已连接素材必须完整包含在所属行内；超出可视高度时由参数清单内部滚动，不能通过压扁参数行塞入同一屏。短文本允许使用紧凑初始高度，长文本保留多行编辑空间。

连接同类输入时，一个可用槽位直接绑定；多个可用槽位弹出官方字段选择；同类槽位全部占用时明确选择替换目标。参数面板不得另设素材选择、顺序交换或来源模式控件；需要改绑时由用户重新连接并选择目标槽位。旧连接没有字段键时只允许按类型顺序兼容回退，用户下一次确认后必须固化字段键。

字段选择器由落线动作打开后必须保持可操作，不能被紧随落线产生的同一次点击事件立即关闭。用户选择字段后才创建带 `targetFieldKey` 的连接；点击外部或按 `Esc` 取消时不创建连接。验收同时覆盖“多个文本/图片槽位待选择”和“同类槽位已满后选择替换”两种情况。

如果应用还有枚举、开关、数字、比例、分辨率、输出形式等不适合通过画布节点连接的字段，应根据官方 Schema 自动渲染为下拉、布尔开关、数字输入、滑块或文本输入。`SELECT/SWITCH` 等带选项字段属于参数，不得因为底层值是字符串而误判为文本素材输入。

运行前必须校验必填输入、数量、类型和参数范围。输出类型根据应用返回 Schema 或实际结果确定。若一次运行只返回一种媒体，则创建对应类型的素材节点并设置为 `result` 状态；若一次运行同时返回多种媒体，则生成一个组合结果组，在组内引用对应类型的素材节点。

运行请求固定使用 AI 应用接口：提交体只包含 `webappId`、`nodeInfoList` 和当前计费 Key 选择，不携带 `workflowId`、工作流 JSON 或 `instanceType`。历史 RunningHub 工作流只能由旧数据迁移层和 MiniMax 专用兼容入口调用，不能回流到新 `RunningHub ComfyUI` 节点。

### 3.9 素材节点的 `result` 状态（从 `smart-image` 拆出）

素材节点只表示一个可被引用的文本、图片、视频或音频媒体，不承担模型配置。它可以处于输入、引用或生成结果状态；`smart-text-generator` 和历史 `smart-prompt` 都只生成文本 `result` 状态。用户可以把同一个素材节点理解为“上传素材”或“生成结果”，但系统不为这两种感知创建两个底层节点类型。

共同能力：

- 显示来源运行节点、平台、模型、运行时间和轮次。
- 展示进行中、成功、失败和可恢复状态。
- 图片展开，视频和音频播放，文本展开阅读。
- 下载、复制、再次作为输入、收藏和从画布移除。
- 打开生成记录和请求参数。
- 与素材库中的同一结果记录保持稳定引用。

**按媒体类型提供的能力**

| 媒体类型 | 当前项目已有或应保留的能力 | 不应直接套用的能力 |
| --- | --- | --- |
| 图片 | 预览、大图查看、下载、收藏、复制引用、裁剪、扩图、遮罩、画笔、宫格切分/拼接、放大、作为下游输入；所有改变图片内容的操作生成新的结果文件，不覆盖源图片 | 视频时间轴、音频波形和音频播放控制 |
| 视频 | 首帧预览、播放/暂停、进度拖动、首帧/当前帧/尾帧导出、时间范围裁剪、抽取音频、下载、收藏、复制引用、在新窗口查看、作为下游输入 | 图片裁剪、遮罩、画笔、宫格切分等静态像素编辑 |
| 音频 | 音频卡片、波形或播放条、播放/暂停、进度控制、时间范围裁剪、下载、收藏、复制引用、作为下游输入 | 图片编辑工具和视频帧工具 |
| 文本 | 展开阅读、复制原文、下载文本、收藏、作为下游输入 | 图片、视频和音频的预览与播放工具 |

当前代码没有独立的 `smart-video` 或 `smart-audio` 节点。视频和音频能力目前挂在原 `smart-image` 混合节点的媒体识别、预览和播放逻辑中；重构后不新增“视频素材节点”或“音频素材节点”两种底层节点，而是由同一个素材节点根据 `media_type` 展示对应工具。

视频和音频还应补齐的专属能力：

- 视频：首帧缩略图稳定生成、完整播放预览、帧导出、视频信息查看、拖动起止手柄的时间范围裁剪，以及抽取完整音频或当前裁剪区间内的音频。
- 音频：可视化波形、播放进度与拖动、播放速度、音量、静音、循环播放、音频时长和格式信息，以及拖动起止手柄的时间范围裁剪。
- 两者都支持双击展开、鼠标悬停播放提示、下载、新窗口查看、复制稳定引用、收藏到资产素材和连接到下游运行节点。

**视频和音频时间范围裁剪**

视频和音频裁剪使用同一套交互模型：用户在展开的预览窗口中看到完整时长和可拖动的时间轴，左右两个手柄分别表示开始时间和结束时间，也可以直接输入精确秒数。用户点击“生成裁剪素材”后，系统按 `[start, end]` 区间生成新的媒体文件，并在源素材节点后方创建一个新的素材节点。

- 原始素材不被修改、不覆盖、不删除，原节点继续引用原始素材。
- 新素材节点使用 `source_asset_id`、`trim_start`、`trim_end` 和 `derived_from` 保存来源关系、裁剪区间和派生操作。
- 视频输出保持可播放性和原始音轨；音频输出保持原始编码可播放性，必要时由服务端转码为兼容格式。
- 裁剪结果进入生成结果或派生结果的持久化目录，并同步写入素材索引；它不是只存在于画布内的临时 Blob。
- 默认名称沿用源文件基础名称并追加区间后缀，例如 `原文件名_3s-5s.mp4`、`原文件名_3s-5s.mp3`；用户可以在素材详情中修改显示名称，但不能修改扩展名和真实媒体类型。
- 相同源文件、相同起止时间和相同编码参数应复用已有派生文件，避免重复占用空间。

**媒体处理结果统一进入生成结果**

凡是会改变媒体内容或从媒体中提取新内容的操作，都视为一次本地媒体生成任务，而不是对原素材的直接修改：

- 图片裁剪、扩图、遮罩、画笔、宫格切分、宫格拼接和放大，生成新的图片结果。
- 视频时间范围裁剪，生成新的视频结果；如果用户同时选择抽取音频，则额外生成新的音频结果。
- 音频时间范围裁剪，生成新的音频结果。
- 视频抽取音频支持抽取完整视频音频，也支持只抽取当前时间范围；输出新的音频素材节点。

处理结果必须写入生成结果存储和素材索引，而不是只在画布中替换源节点内容。新结果节点保存 `source_asset_id`、`derived_from`、处理类型、起止时间、编码参数和生成时间。源素材节点仍然可以播放、下载、收藏、再次输入或继续生成。

视频抽取音频的默认命名沿用视频源文件基础名称并追加 `_audio`，例如 `原视频_audio.mp3`；如果指定了时间范围，再追加 `_3s-5s`。音频裁剪沿用音频源文件基础名称并追加时间范围，例如 `原音频_3s-5s.mp3`。结果文件进入素材库“生成结果 / 音频”，并可继续拖入画布或连接到支持音频输入的运行节点。

**文本结果的预览、编辑与优化**

- 当前素材库已经使用纯文本读取和 `<pre>` 预览，并支持展开与复制；智能画布的文本输出尚未形成独立的文本结果数据契约。
- 新版文本结果必须保存原始 Markdown 文本，不把渲染后的 HTML 当作源文件，也不把渲染结果另存为第二份内容。
- 默认使用安全的 Markdown 预览，以便标题、列表、引用、代码块和表格更易阅读；复制操作始终复制原始 Markdown 文本。
- 双击文本素材进入编辑状态，默认显示 Markdown 源文。编辑过程中只维护草稿；取消时丢弃草稿，保存时生成新的文本结果和新的素材节点，原文本结果保持不变。
- 文本工具栏提供预览/源码切换、编辑、复制原文、下载 Markdown、收藏、字数与字符数、查看来源和版本关系。
- “AI 优化”允许选择已配置的文本平台和模型、一个或多个 Skill、提示词模板或自定义指令；当前文本作为用户输入，Skill 内容作为系统能力上下文。
- AI 优化输出新的文本结果，并保存 `source_asset_id`、`derived_from=text_edit|skill_optimize`、Skill 内容快照、Skill 稳定 ID、平台、模型、用户指令、参数和生成时间。
- Skill 更新后，历史运行继续使用保存的快照；用户主动点击“更新到最新版”后，只影响后续运行，不改写已有结果。
- Markdown 解析失败、内容类型不明或浏览器能力不足时，自动退回纯文本预览，不能阻塞结果读取。
- 需要限制或清理危险 HTML，避免模型输出中的脚本或外部内容被直接执行；第一阶段使用 Markdown 源码编辑器，不做复杂的富文本编辑器。

素材节点还需要支持“同一媒体类型的轮内多结果”结构：

```text
第 1 轮素材节点（`result`）
├─ 图片 1
├─ 图片 2
└─ 图片 3
```

轮内每一项结果都必须有自己的稳定 `result_id`，同一媒体类型默认在同一个素材节点内展示，节点通过有序 `result_ids` 保存内部结果，避免一次批量生成造成大量画布节点。单项拖出、单项连线或单项删除只操作对应结果引用，不复制文件，也不破坏同节点内其他结果。若同一次运行返回不同媒体类型，则按类型创建多个素材节点，并由一个组合结果组统一引用。

### 3.10 结果组节点（组合节点）

结果组节点是一个可展开、可连接、可提取内部结果的结构容器。它用于循环节点的打组结果、AI 应用一次运行产生的多媒体组合结果，也可用于用户主动整理多个结果。它不是新的文件存储类型，也不是素材节点；它只保存对多个素材节点或结果项的结构化引用集合。

现有基础：可复用 `smart-group` 的容器布局、自动整理、成员拖出和连线收拢交互，但不能直接沿用它当前的 `images/items` 数据结构。结果组必须新增稳定结果引用和类型化输出语义，避免把“看起来分在一起”误当成“数据上属于同一组”。

结果组分为两种结构：

- 循环结果组：按轮次组织同一运行流程多次执行产生的结果。
- 组合结果组：组织一次运行同时产生的文本、图片、视频、音频等不同类型结果。

结果组必须保留：

- 组 ID。
- 来源循环节点或运行节点。
- 轮次顺序。
- 每轮素材节点 ID。
- 每项结果的稳定结果 ID。
- 原始输入、提示词、平台、模型和运行时间摘要。

示例：

```text
循环结果组
├─ 第 1 轮 → 素材节点（`result`）→ 图片 1、图片 2
├─ 第 2 轮 → 素材节点（`result`）→ 图片 1、图片 2
└─ 第 3 轮 → 素材节点（`result`）→ 图片 1、图片 2
```

```text
AI 应用组合结果组
├─ 文本素材节点（`result`）
├─ 图片素材节点（`result`）
├─ 视频素材节点（`result`）
└─ 音频素材节点（`result`）
```

结果组只保存引用关系，不复制结果文件。删除结果组或从画布移除结果组，不删除其中引用的生成结果；用户必须在素材库中明确删除结果文件，文件才会被删除。

结果组必须同时提供两级输出能力：

- 整体输出：从结果组主端口拉线，将组内全部结果连同类型、顺序、轮次和来源关系一起传给后续节点。
- 单项输出：从组内某个素材节点或结果项的独立端口拉线，只传递该项结果。
- 提取到画布：用户可将组内某个结果拖出，形成可独立摆放和连线的素材节点引用；该操作不复制文件，也不默认从原结果组删除该项。
- 移出结果组：如果用户确实要修改结果组结构，应使用明确的“移出结果组”操作，避免普通拖拽意外破坏原有组合关系。

结果组折叠时仍显示组级主端口；展开时显示内部素材节点及其单项端口。组级连线和单项连线可以同时存在，且必须共同引用同一批稳定结果 ID。

结果组可以作为后续运行节点的输入。接收方需要明确选择输入展开方式：

- 按轮次输入：保持第 1 轮、第 2 轮的对应关系。
- 按结果项输入：将组内所有结果作为一个序列输入。
- 选择单项输入：从组内选择指定轮次和结果项。

默认优先使用“按轮次输入”，这样循环套循环时可以保持每一轮的输入输出对应关系；不支持组输入的模型必须在运行前提示用户先展开或选择单项。

## 四、模型能力定义与动态界面

### 4.1 能力定义不是模型名称列表

API 设置不能只保存 `image_models`、`chat_models` 和 `video_models`。每个模型还需要一份能力定义，用于描述操作、输入、参数和输出。

示例：

```json
{
  "provider_id": "ai-money",
  "model_id": "seedance-2.0-fast-i2v",
  "media_type": "video",
  "operations": {
    "image_to_video": {
      "inputs": {
        "text": {"min": 1, "max": 1},
        "image": {"min": 1, "max": 1, "roles": ["first_frame"]},
        "video": {"min": 0, "max": 0},
        "audio": {"min": 0, "max": 0}
      },
      "parameters": {
        "duration": {"type": "select", "options": [5, 10]},
        "resolution": {"type": "select", "options": ["720p", "1080p"]},
        "aspect_ratio": {"type": "select", "options": ["16:9", "9:16"]}
      },
      "output": {"type": "video", "count_min": 1}
    }
  }
}
```

### 4.2 能力数据来源

按可靠性依次使用：

1. 平台接口直接返回的模型 Schema。
2. 平台官方文档维护的项目内置能力模板。
3. 用户在 API 设置中手动补充或修改的能力定义。
4. 无法确认能力的通用兼容模型，只开放经过验证的基础参数。

AI MONEY、RunningHub、火山、即梦等固定平台应维护可更新的能力模板。RunningHub AI 应用优先读取远端字段并保存本地快照，避免每次打开画布都依赖远端请求；旧工作流快照只用于历史兼容，不进入新配置入口。

### 4.3 筛选顺序

```text
节点类型
→ 当前已连接的文本、图片、视频、音频及数量
→ 输入角色
→ 兼容平台
→ 兼容模型
→ 兼容操作模式
→ 动态参数界面
```

筛选结果只显示能够完整接收当前输入组合的选项。连接变化后重新计算兼容项；如果当前模型因此失效，界面必须解释冲突原因并要求用户重新选择，不能静默换成另一个模型后直接运行。

### 4.4 先建立事实全集，不把全集直接画成表单

用户提出的“调查各平台真实模型，再按文本、图片、视频、音频提取全部已成立能力”的方向正确。需要校准的是：能力全集属于**登记层**，不是节点上永远显示的固定控件全集。

```text
官方接口和当前适配器确认的模型能力
→ 按文本、图片、视频、音频建立能力登记表
→ 当前输入筛选操作模式
→ 当前平台和模型筛选可用字段
→ 只渲染本次真正有效的输入和参数
```

例如图片类登记表可以包含文本、参考图片、遮罩图片、比例、分辨率、输出数量等语义，但用户选择一个只支持文生图的模型时，界面只显示该模型已确认支持的文本输入和参数；不能因为其他图片模型支持遮罩，就把遮罩控件也显示出来。

能力全集每个字段必须标记来源模型、操作模式、证据来源和可信度。没有证据的参数不能因为“同类模型一般都有”而加入。

### 4.5 五类内容必须分开

过去的方案把模型接口、素材处理和效率功能混在一起，需要改为五类：

| 分类 | 含义 | 是否进入普通模型参数区 | 示例 |
| --- | --- | --- | --- |
| 模型必填输入 | 缺少后模型不能执行 | 是，突出显示 | 提示词、首帧图、参考音频、待编辑视频 |
| 模型可选参数 | 接口明确支持但不是必填 | 是，仅在当前模型支持时显示 | 比例、分辨率、时长、输出格式、生成音频 |
| 模型高级参数 | 接口确实支持，但普通用户低频使用 | 进入“高级参数”，默认收起 | 随机种子、负面提示词、采样器、CFG、提示词扩展模式 |
| 画布素材处理 | 在调用模型前改变或派生素材 | 否，属于素材节点工具 | 裁剪、缩放、遮罩绘制、视频裁剪、视频抽音频 |
| 用户效率工具 | 帮助用户准备输入或编排任务 | 否，独立于目标模型参数 | 提示词优化、Skill、模板、循环、重试、批量运行 |

平台认证、任务轮询、计费、上传 URL、响应路径等属于协议内部字段，不进入用户参数区。

**种子如何处理**：调查证实 AI MONEY 部分视频和 Qwen 图片接口、部分 RunningHub 工作流确实支持 `seed`。因此种子不是臆造参数，但也不是所有图片或视频节点的默认参数。它只在选中的模型档案明确支持时出现在“高级参数”，默认使用平台随机值。

**遮罩如何处理**：画布负责绘制并生成遮罩素材；如果具体模型接口明确接收 `mask`，执行节点再把该素材识别为“遮罩图片”输入角色。当前项目的 OpenAI 图片编辑路径确实会提交 `mask`，但不能因此推断 ModelScope、RunningHub 或 AI MONEY 的所有图片模型都支持遮罩。

**生成数量如何处理**：接口明确支持 `n`、`count` 或批量输出时，它是模型参数；模型不支持时，由现有循环节点负责多次调用。不得把循环次数伪装成模型的生成数量字段。

本轮调查日期更新为 2026-08-13，事实来源包括：

- 当前配置：`data/api_providers.json`。
- 当前请求实现：`main.py` 中的 ModelScope、RunningHub、AI MONEY、通用 OpenAI 图片、视频和 LLM 适配器。
- 当前界面判断：`static/js/smart-canvas.js` 中的 ModelScope 模型能力和 RunningHub 动态字段。
- AI MONEY 官方 AI 接入文档：`https://api.laohuaimoney.com/docs/llms.txt`。
- RunningHub 官方模型注册表：`https://raw.githubusercontent.com/HM-RunningHub/ComfyUI_RH_OpenAPI/main/models_registry.json`。
- RunningHub 在线画布：`https://rhtv.runninghub.cn/project/canvas/2087789524588519426`，仅用于核对模型分类和选择路径，不作为接口字段证据。
- ModelScope 当前已配置模型的模型卡和项目实际请求字段。

能力档案使用以下可信度：

1. `runtime_verified`：当前项目已有请求或测试证明字段真正参与调用。
2. `official_schema`：平台提供机器可读 Schema，例如 RunningHub 模型注册表。
3. `official_documented`：官方文档明确列出字段、范围和依赖，例如 AI MONEY 文档。
4. `model_card_only`：模型卡只说明能力方向，没有证明当前平台接口接受哪些字段。
5. `unknown`：只有模型名称或模型列表，没有参数证据。

只有前三类能够自动生成可运行控件。`model_card_only` 只能用于能力提示，`unknown` 不参与自动运行。

固定目录平台与开放模型平台采用不同维护方式：

- AI MONEY、RunningHub 官方注册表等有明确目录和 Schema 的平台，可以同步完整目录并生成能力档案。
- ModelScope、火山接入点和自定义 OpenAI 兼容平台允许用户添加任意模型，不能承诺预先穷举全网模型；只为当前启用模型建立档案，未知模型进入待确认状态。
- 火山引擎当前配置没有添加聊天、图片、视频或音频模型，本轮不凭空补充模型能力。

#### 4.6.2 目录发现不等于模型可运行

即使用户已经把目录中的全部模型加入 API 设置，系统也必须继续区分以下阶段：

```text
目录发现
→ 输出类型校正
→ 产品模型家族归并
→ 任务变体和参数 Schema 建档
→ 标准请求映射
→ 平台适配器可用
→ 静态契约通过
→ 经授权的真实运行验证
```

API 设置中的“已启用”只表示用户允许画布使用该候选模型。只有能力档案有可靠证据、标准字段能完整映射、适配器支持对应操作并通过静态契约测试时，模型才进入节点的可运行列表。目录可见但缺少其中任一项时，保留在 API 设置中并说明“待补能力档案”或“适配器未完成”，不得把粗分类直接变成运行能力。

API 设置的每个已启用模型必须直接显示运行准备度：“已适配”表示可进入画布候选；“待补能力档案”表示只有目录或粗分类信息；“适配器未完成”表示接口能力已经确认，但项目还没有完成标准请求到平台请求的转换。状态来自后端能力目录，不由前端根据名称猜测。用户删除某个模型后，它立即退出当前启用清单和新建节点候选，但历史画布仍保留当时的模型与能力快照。

档案事实状态继续使用 `confirmed/pending/deprecated`，表示能力证据是否成立；运行准备度单独使用 `ready/needs_profile/adapter_missing/deprecated`，表示当前设备和适配器能否执行。二者不能共用一个 `status` 字段：`confirmed + adapter_missing` 表示接口事实明确但项目尚未完成调用转换，仍不能运行。

### 4.7 当前事实矩阵与第一版节点边界

当前配置包含 ModelScope、RunningHub、火山引擎和 AI MONEY。根据当前配置、项目代码和官方资料，第一版界面边界如下。

#### 4.7.1 文本生成

文本生成由 `smart-text-generator` 承担；历史 `smart-prompt` 只作为旧画布兼容入口。

- 当前项目实际请求支持：节点用户文本、系统提示词、历史消息、图片和视频；视频在部分路径中会转换为关键帧。文本节点已将图片、视频和音频输入纳入能力筛选和标准请求对象。
- 当前已配置 ModelScope 文本模型中，只有模型档案明确为视觉模型时才开放图片或视频输入；纯文本模型不能因为后端能够构造多模态消息就自动接收图片。
- AI MONEY 官方当前文本接口 `kimi-k3` 文档只确认文本消息、流式开关和最大输出长度；未确认的图片、视频和音频输入不得开放。
- Skill、提示词模板和提示词优化属于效率工具，不是目标文本模型的媒体输入参数。

第一版稳定区域：平台、模型、用户文本、可选系统提示词。图片、视频和音频根据模型档案动态出现；音频理解在通用 OpenAI 兼容适配器中仍会在发送前明确拒绝，待具体平台适配器完成后才开放运行。

#### 4.7.2 图片生成

当前已确认的输入语义全集为：文本、参考图片；遮罩图片只在接口明确支持时作为特殊图片角色出现。

当前已确认的可选参数全集为：比例或尺寸、分辨率、输出数量、质量、输出格式；种子、负面提示词和提示词扩展只属于部分模型的高级参数。

事实样本：

- RunningHub 当前配置的 `gpt-image-2.0/text-to-image-channel-low-price`：文本、比例、分辨率。
- RunningHub 当前配置的 `gpt-image-2.0/edit-channel-low-price`：文本、1 至 10 张图片、比例、分辨率。
- AI MONEY 当前配置的 `laohuaimoney-image-g-v2-lowprice`：文本、可选图片、`1k/2k/4k`、比例或尺寸、`n=1..10`。
- ModelScope 当前项目明确把 Z-Image 作为文生图，把 Qwen Image Edit 和 FLUX.2 Klein 作为可接收图片的编辑模型；通用后端虽然能够发送 `image_url`，但不能据此认定所有 ModelScope 图片模型都支持图生图。

裁剪、缩放、扩图画布、遮罩绘制、宫格拆分或拼接仍是素材处理工具。处理完成后产生新的图片素材，再作为参考图片或遮罩图片输入执行节点。

#### 4.7.3 视频生成

已确认的输入语义全集为：文本、图片、视频、音频。图片还可按模型细分为首帧、尾帧、多参考图；视频可作为待编辑视频或参考视频；音频可作为参考音频。

已确认的可选参数全集为：时长、比例、分辨率、是否生成音频、是否返回尾帧。种子、负面提示词、提示词扩展、安全等级等只在具体模型支持时进入高级参数。

AI MONEY 官方文档已经证明不同视频模型差异很大：

- 文生视频只需要文本。
- 图生视频需要 1 至 2 张图片，分别承担首帧和尾帧角色。
- 多模态视频可以接收图片、视频和音频，但数量上限随 Seedance 2.0、2.5 或其他模型变化。
- 部分模型时长固定，部分允许范围选择；部分支持生成音频，部分不支持。

因此视频节点不能预先固定一套“所有模型都可用”的表单。用户连入素材后先筛操作模式和模型，再显示该模型真实支持的角色、数量和参数。

#### 4.7.4 音频生成

当前已确认的输入语义全集为：文本、参考音频、参考图片；音色 ID属于模型参数而不是素材。不同输入之间可能互斥。

AI MONEY 官方文档确认：

- `doubao-seed-audio-1.0` 使用文本，可选音色、参考音频或参考图片，三类参考方式存在互斥关系；支持格式、采样率、语速、响度和音高。
- `whisper-1` 是音频转文本，不是音频生成；应作为独立操作或后续转写节点能力，不混入首版音频生成表单。

音频节点只显示 `audio_generation` 档案。视频抽音频、音频裁剪、音量和变速属于素材处理，不是生成模型参数。

#### 4.7.5 音乐生成

当前已确认的输入语义全集为：文本和模型明确支持的参考音频；歌词、是否纯音乐、风格和输出数量属于模型参数。

AI MONEY 官方文档确认：

- `mureka-v8-bgm` 与 `mureka-v9-bgm` 使用文本或已有伴奏 ID，支持 1 至 3 个输出。
- MiniMax Music 使用文本，可配置歌词、纯音乐、格式、采样率和码率。
- Suno 音乐属于独立音乐任务集合，不同动作需要不同的任务 ID、参考音频或版本参数，不能直接套用语音表单。

音乐节点只显示 `music_generation` 档案，并使用独立预检和 `/api/canvas-music` 路由。音乐结果仍保存为音频素材，但不会因此进入音频生成节点的模型候选集。

### 4.8 节点界面由能力档案实例化

节点的稳定部分只有：操作模式区域、输入区域、平台与模型选择、动态参数容器、效率工具区域、运行状态。具体输入槽和参数控件由模型能力档案实例化，不在节点代码中永久写死。

```text
读取已连接素材类型和数量
→ 推导候选操作模式
→ 筛选可完整接收当前输入的平台和模型
→ 用户选择平台和模型
→ 显示该模型必填输入
→ 显示该模型可选参数
→ 高级参数默认收起
→ 独立显示素材处理入口和效率工具
```

参数控件有四种状态：

- **必填**：当前模式运行所需，缺少时说明缺什么并禁止运行。
- **可选**：当前模型支持，用户不设置时使用模型档案中的官方默认值。
- **高级**：当前模型支持但低频，默认收起；例如种子。
- **不适用**：切换模型后原值暂时保留但不发送，界面明确说明当前模型不支持。

不允许出现“用户选了参数，但请求中静默忽略”的情况。

#### 4.8.1 模型家族、部署路由和任务变体

同一产品模型常由多个真实接口组成。例如用户理解的 `Seedance 2.0 Fast`，平台可能分别提供文生视频、图生视频和多模态视频模型 ID。画布不能把所有后缀直接堆进模型下拉框，也不能仅凭输入数量拼接模型名称。

模型身份拆成三层：

1. **产品模型家族**：用户选择的名称，例如 `Seedance 2.0 Fast`。同一平台、同一产品代际和性能档位归为一个家族。
2. **任务变体**：实际能力和接口，例如 `text_to_video`、`first_frame_to_video`、`start_end_to_video`、`reference_to_video`、`multimodal_video`、`video_edit`。
3. **部署路由**：平台真实的模型 ID、endpoint、站点和计费通道。国内站、国际站、低价通道或 VIP 通道属于部署信息，不应伪装成新的产品模型家族。

示例结构：

```json
{
  "family_id": "seedance-2.0-fast",
  "display_name_zh": "Seedance 2.0 Fast",
  "provider_id": "ai-money",
  "variants": [
    {"variant_id": "text_to_video", "upstream_model_id": "seedance-2.0-fast-t2v"},
    {"variant_id": "image_to_video", "upstream_model_id": "seedance-2.0-fast-i2v"},
    {"variant_id": "multimodal_video", "upstream_model_id": "seedance-2.0-fast-multi"}
  ]
}
```

RunningHub 国内站和国际站可以分别保存目录和凭据，但画布只读取当前生效站点；站点切换只改变该平台的部署路由，不在画布中生成两个 RunningHub 平台或两份同名模型。

#### 4.8.2 统一任务语义

平台自己的 endpoint 名称先映射到稳定任务语义，再进入节点。首批语义如下：

| 节点 | 任务语义 |
| --- | --- |
| 文本生成 | `text_to_text`、`image_to_text`、`video_to_text`、`audio_to_text`、`multimodal_to_text` |
| 图片生成 | `text_to_image`、`image_to_image`、`image_edit`、`layer_decomposition`、`image_upscale` |
| 视频生成 | `text_to_video`、`first_frame_to_video`、`start_end_to_video`、`reference_to_video`、`multimodal_video`、`video_edit`、`video_extend` |
| 音频生成 | `text_to_speech`、`text_to_audio`、`voice_clone`、`voice_design`、`audio_edit` |
| 音乐生成 | `music_generation`、`music_to_music`、`text_to_music`、`lyrics_to_music` |

输出类型决定结果进入哪个素材节点。`image_to_text`、音频转写等虽然使用媒体输入，但输出是文本，应进入文本生成节点的候选能力和文本结果；视频补帧、放大等如果只是确定性素材处理，应留在素材工具，不因平台把它列为模型就强行混入视频生成主流程。

#### 4.8.3 节点选择与自动路由

参考 RunningHub 在线画布的有效思路，但不照搬其界面：先按节点和任务能力缩小范围，再按模型家族展示。视频节点可显示“文生视频、首帧、首尾帧、多图参考、视频参考、视频编辑、视频延长”等操作；模型列表按 Seedance、Kling、MiniMax、Wan、Vidu 等家族归组，而不是把每个上游后缀平铺展示。

路由按以下优先级求唯一变体：

```text
用户显式选择的操作模式
→ 当前输入素材的类型、角色和数量
→ 当前模型家族支持的候选变体
→ 必填参数和互斥条件是否满足
→ 当前平台生效站点与适配器是否可用
→ 唯一的真实模型 ID和 endpoint
```

如果多个变体仍然都能匹配，界面要求用户选择操作模式或输入角色；如果没有变体匹配，明确指出不兼容的素材、数量或缺失参数。系统不得静默改用另一个模型家族，也不得把首帧和参考图等不同角色仅按连线顺序猜测。

### 4.9 能力档案结构

```json
{
  "provider_id": "runninghub",
  "model_id": "gpt-image-2.0/edit-channel-low-price",
  "node_type": "image_generation",
  "operation": "image_to_image",
  "version": 1,
  "evidence": {
    "level": "official_schema",
    "source": "runninghub-model-registry",
    "checked_at": "2026-08-12"
  },
  "inputs": {
    "text": {"min": 1, "max": 1, "roles": ["prompt"]},
    "image": {"min": 1, "max": 10, "roles": ["reference"]}
  },
  "parameters": {
    "aspect_ratio": {"level": "optional", "type": "enum", "default": "empty"},
    "resolution": {"level": "optional", "type": "enum", "options": ["1k", "2k", "4k"], "default": "1k"}
  },
  "request_mapping": {
    "prompt": "prompt",
    "image.reference": "imageUrls",
    "aspect_ratio": "aspectRatio",
    "resolution": "resolution"
  },
  "output": {"type": "image", "count_min": 1}
}
```

`inputs` 只描述模型真正接收的输入；素材处理工具不写进这里。`parameters` 只描述接口真实支持的选项；效率工具不写进这里。复杂互斥和依赖使用 `required_when`、`visible_when`、`conflicts_with` 表达。

模型家族档案负责产品名称和变体集合；变体能力档案继续使用 `provider_id + model_id + node_type + operation` 唯一标识真实接口。这样历史画布仍能保存并恢复准确的上游模型 ID，新画布则只把家族名称作为主要选择项。

### 4.10 API 设置中的模型接入

API 设置中的“添加模型”需要完成模型名称与能力档案绑定：

1. 用户选择聊天、图片、视频或音频分类并添加模型。
2. 有官方 Schema 的平台自动读取模型字段；有固定官方文档的平台匹配内置档案。
3. 匹配成功后展示操作模式、输入要求、参数摘要、证据来源和更新时间。
4. 只有模型名称但没有能力证据时，标记“能力待确认”，不能凭模型类别自动开放所有参数。
5. 用户可以在高级设置补充自定义模型档案，但必须通过字段校验、语义校验和静态请求快照测试；普通连接测试只能证明地址和认证可达，不能标记为真实生成已验证。
6. 能力档案更新后生成新版本；旧画布和历史结果继续保存原版本快照。

`image_models`、`chat_models`、`video_models`、`audio_models` 继续作为兼容索引，但不再作为能力事实来源。

#### 4.10.1 用户视角的模型生命周期

API 设置中的模型分为三个状态，必须在界面和运行逻辑中保持一致：

1. **上游目录**：点击“拉取模型”得到的全部候选，只代表平台返回了这些模型。
2. **画布启用清单**：用户按文本、图片、视频、音频分类点击“选择模型”并保存后，模型才进入当前平台的启用清单。
3. **画布可运行候选**：启用清单与能力档案、适配器和 `readiness=ready` 求交集后，才显示在新建运行节点中。

用户删除模型属于“停用当前模型”，不删除平台适配器、能力档案、Manifest 或历史画布快照；删除后模型必须立即从新建节点候选和模型筛选结果中消失。历史节点可以继续展示原模型和能力快照，但再次运行时若模型已停用或档案已失效，必须提示重新选择，不能偷偷替换为相似模型。

### 4.11 请求映射、快照与异常

运行前先生成平台无关的标准请求，再由平台适配器转换真实字段。标准请求保存平台、模型家族、任务变体、真实模型 ID、操作模式、能力档案版本、输入素材 ID及角色、有效模型参数、提示词或 Skill 快照和追踪 ID。

后端必须使用同一份能力档案再次校验输入类型、数量、角色、必填条件、互斥条件、参数范围和请求映射。前端显示不是唯一约束。

- 参数无法映射时，运行前指出具体字段，不静默丢弃。
- 模型下线时保留历史配置和结果，再次运行要求重新选择。
- 平台返回非 JSON 或错误页时，先识别 HTTP 状态和内容类型，再生成统一错误。
- 模型列表有但档案未知时，只显示“待确认”，不参与自动兼容筛选。
- 平台或模型切换时保留用户提示词和素材连接；不适用参数保留草稿但不发送。

### 4.12 当前项目的实施顺序

1. 固化统一任务语义、输入角色、证据等级和标准请求 Schema。
2. 保存各平台只读目录快照，先校正输出类型，再建立产品模型家族和任务变体；目录名称不得直接写成可运行档案。
3. 把 RunningHub 官方 401 条注册表转换成带 endpoint 和参数 Schema 的候选变体；把 AI MONEY `llms.txt` 转成逐任务变体并修复 `/models` 粗分类。
4. 为当前启用的 ModelScope 模型逐个补证据；即梦 CLI 使用本地命令能力清单；GPT CLI 只建立文本能力。火山本轮明确延期。
5. 将现有图片、视频、音频、LLM、RunningHub、AI MONEY、ModelScope 和 CLI 调用器包装为统一平台适配器，不重写已经可用的请求、轮询和结果落地链路。
6. 在 `smart-text-generator` 和三类媒体生成节点中接入“操作模式 → 模型家族 → 任务变体 → 动态参数”的筛选；AI 应用继续按远端字段 Schema 生成界面。
7. 将提示词优化、Skill 和模板放入效率工具区，将裁剪、遮罩制作、视频裁剪和抽音频保留在素材节点工具区。
8. 用固定测试夹具和禁止触网的 dry-run 验证“输入变化 → 家族筛选 → 变体路由 → 参数显示 → 平台请求快照 → 结果类型”，本阶段不提交真实生成任务。

首批实现不追求一次性手工录入全网模型。固定目录平台通过同步更新，开放平台按用户实际启用模型逐个建立可验证档案；这样既以事实为准，也避免能力表快速失真。

### 4.13 能力档案独立存储与维护

模型接口、模型能力和参数映射不再继续堆在 PRD、API 设置页面或节点代码中。当前项目采用“稳定规范 + 平台档案 + 用户接入配置 + 设备运行状态”四层结构：

官方维护范围固定为六个平台：ModelScope、RunningHub、火山引擎、AI MONEY、即梦 CLI 和 GPT CLI（OpenAI Codex CLI）。项目维护这六个平台的模型目录、产品模型族、能力档案、节点语义映射、真实接口路由和兼容性测试；用户只填写自己的 API 凭据、选择站点或完成本机 CLI 登录，不直接修改官方适配规则。

RunningHub 在产品和画布中始终只算一个平台。API 设置允许分别保存国内站和国际站的 Base URL、RH币 Key、账户余额 Key、模型目录和 AI 应用，但必须同时保存一个唯一的“当前生效站点”。切换生效站点后，系统只把该站点的模型、AI 应用、地址和凭据投影到 RunningHub 顶层配置并提供给画布；未选中的站点只用于 API 设置中的备用配置，不进入画布平台列表、模型下拉、AI 应用下拉、能力目录或运行请求。禁止把两站合并展示，也禁止将其拆成“RunningHub 国内站”和“RunningHub 国际站”两个画布平台。

Antigravity CLI 不属于官方平台，也不进入本阶段的智能画布能力适配、连接测试和回归验收。它与其他用户自行添加的平台统一视为自定义或实验接入：项目可以保留通用接入入口和已有代码，但不承诺模型目录、能力映射、安装登录或版本兼容性，由添加者自行配置和维护。自定义接入不得修改画布稳定语义、官方能力档案或共用运行协议；需要特殊行为时通过受控平台适配层扩展。

| 层级 | 路径 | 责任 | 变化频率 |
| --- | --- | --- | --- |
| 稳定规范 | `docs/model-capabilities/`、`data/model_capabilities/capability-vocabulary.json` | 统一媒体类型、输入角色、参数等级、证据等级、档案格式和维护流程 | 低 |
| 平台能力档案 | `data/model_capabilities/providers/*.json` | 记录平台当前模型、操作模式、输入数量、参数、请求映射、输出和官方来源 | 中高 |
| 用户接入配置 | `data/api_providers.json`、`API/` | 记录用户添加的平台、地址、启用模型、协议和密钥 | 高频 |
| 设备运行状态 | `data/settings/cli_runtimes.json` | 记录本机 CLI 路径、安装检测、版本、WSL 与非敏感登录状态；不进入工作流导出 | 高频 |

总入口是 `data/model_capabilities/registry.json`。程序先读取索引，再读取对应平台档案，最后与 `data/api_providers.json` 中用户实际启用的模型求交集；如果平台使用本地 CLI，再读取当前设备的 `cli_runtimes.json` 判断是否可执行。这样 API 设置负责“用户接入了什么”，能力档案负责“这个模型经过证据确认能做什么”，设备状态负责“这台电脑现在能不能运行”，运行节点负责“当前连接的输入要显示什么”，四者职责不会混在一起。

能力档案必须保存证据等级、来源地址或代码位置、核对日期、版本和状态。模型名称列表不能单独证明参数能力；只有 `runtime_verified`、`official_schema` 或 `official_documented` 的字段才能自动生成可运行控件。`model_card_only` 和 `unknown` 只能进入待确认状态。平台或模型更新时保留旧版本，历史运行保存能力档案快照，避免后续文档变化改写过去的结果解释。

能力档案还必须明确区分模型接口输入、模型参数、素材处理、效率工具和平台内部协议字段。裁剪、缩放、遮罩绘制、视频裁剪、视频抽音频属于素材处理；提示词优化、Skill、模板和循环属于效率工具；上传地址、任务 ID 和轮询状态属于平台内部字段，它们都不应伪装成所有模型通用的参数。

机器读取的 JSON 文件使用 ASCII 文件名和项目相对路径，以兼容 macOS 与 Windows；维护说明使用中文。档案内不得出现 API Key、Cookie、用户素材绝对路径或完整授权头。具体更新步骤和检查清单见 `docs/model-capabilities/能力档案维护规范.md` 与 `docs/model-capabilities/平台适配说明.md`。

### 4.14 能力档案更新、校验和回滚

能力档案属于运行依赖，不能因为一次远端同步、人工编辑或 JSON 损坏让所有节点无法打开。内置档案和远端同步结果在启用前必须通过 Schema、语义引用、模型唯一性、请求映射和证据等级校验；校验失败时继续使用最近一次有效版本，并在 API 设置中显示具体错误和来源。

档案更新使用临时文件和原子替换，运行中的任务固定使用提交时的版本，不因热更新改变参数解释。新档案使当前节点模型失效时，只将节点标记为“档案已更新，请检查”，不自动替换模型或改写参数。维护者可以查看当前版本、上一个有效版本、变更摘要和回滚入口。

远端平台目录和 Schema 使用带更新时间的本地缓存；离线或平台不可访问时继续使用最近一次有效快照。缓存过期只影响“是否最新”的提示，不得把已经验证且仍可运行的本地档案直接清空。

CLI 平台能力档案至少拆分为 `data/model_capabilities/providers/jimeng-cli.json` 和 `data/model_capabilities/providers/codex-cli.json`。前者维护即梦图片/视频命令，后者只维护 Codex 文本能力；设备状态不写进这两个档案。

### 4.14.1 自定义第三方平台：用户视角的完整闭环

本节是当前规范的初版，不把理论设计视为一次性定稿。官方平台先按同一套标准请求和能力档案完成适配；每完成一个平台，都用真实官方 Schema 对照实现，并根据实际字段、错误和参数展示反馈修订规范、档案格式或节点表现。

用户自定义平台的目标是“自己维护平台接入，不修改画布稳定逻辑”。用户从 API 设置的“添加平台”入口开始，填写平台名称、稳定 ID、Base URL 和 Key；平台字段、模型能力、输入角色、参数类型、提交/轮询/结果映射由用户本地的 Agent 根据第三方文档生成。项目提供以下固定入口：

- `GET /api/provider-integration-guide`：人类阅读的接入规范 `docs/第三方API平台接入规范.md`。
- `GET /api/provider-manifest-schema`：机器读取的 `data/model_capabilities/provider-manifest.schema.json`。
- `POST /api/provider-manifests/validate`：不触网的 Manifest 结构和安全校验。
- `POST /api/model-capabilities/dry-run`：不发送上游请求的输入角色、参数、变体和平台请求快照校验。
- `GET /api/model-capabilities`：画布使用的运行时能力目录。

Agent 的最小工作顺序如下：

```text
读取 AGENTS.md、PRD、接入规范、Manifest Schema 和现有适配器
→ 阅读第三方官方文档并提取模型目录、输入、参数、任务和错误
→ 生成 Provider Manifest 与平台能力档案
→ 将第三方字段映射到标准输入角色、参数和输出
→ 仅在受控适配器中实现认证、上传、提交、轮询和结果落地
→ 运行 Manifest 校验、标准请求校验、请求快照和节点契约测试
→ 用户回到 API 设置填写 Key、拉取目录并选择启用模型
```

模型必须区分三个状态：

1. **上游目录**：平台返回的全部模型名称和元数据，只代表“可发现”。
2. **用户启用清单**：用户在 API 设置四类模型中主动保留的模型；删除/停用只改变当前用户配置。
3. **画布可运行候选**：用户启用清单与能力档案、适配器和 `readiness=ready` 的交集，并通过当前输入角色、数量和参数筛选。

因此，用户可以先拉取全部模型，再按文本、图片、视频、音频分类停用模型。停用模型不会进入发布节点的模型家族、模型下拉或真实请求；不会删除能力档案、Manifest、适配器、历史画布或历史结果。历史节点仍显示保存的模型与档案快照，但再次运行时若模型已停用或档案失效，必须提示重新选择，不能静默切换到相似模型。

标准请求是第三方平台与画布之间唯一稳定的中间层。其最小信息包括平台、模型家族、任务变体、真实模型 ID、节点类型、能力档案版本、输入素材及角色、有效参数、提示词/Skill 快照和追踪 ID。第三方的 `input2`、`image_url`、`image_urls`、`frames` 等字段不得直接成为画布语义；它们只能出现在平台档案的 `request_mapping` 或受控适配器中。

本节的验收不要求真实生成或付费调用。必须能够证明：用户启用/停用模型后候选集变化正确；输入文本、图片、视频、音频及首帧/尾帧角色变化后候选变体变化正确；动态参数只来自当前档案；dry-run 返回 `network_requested=false`；不支持的输入、参数或适配器状态由后端拒绝。

当前初版已经提供接入规范、Manifest Schema、本地校验和 dry-run 接口，并在自定义平台的 API 设置页提供“查看规范”“查看 Schema”和“复制 Agent 指令”。复制指令按当前中英文界面生成，并自动带入平台名称与 Base URL；Key 和用户素材不得进入指令。用户拉取目录后，仍需按文本、图片、视频、音频保存自己的启用清单，画布只消费启用清单与 `readiness=ready` 的交集。

这部分尚未宣告稳定。后续必须用 RunningHub、AI MONEY、ModelScope 和至少一个自定义平台依次完成“目录夹具 → 映射工作表 → 标准请求 → 平台请求快照 → 节点参数展示”的无付费对照。若实际官方 Schema 无法由当前规范表达，先修正规范、能力词典或 Manifest Schema，再修改适配器；不得为了通过单个平台而把特例写回公共画布节点。

### 4.15 本地 CLI 平台适配

CLI 与远程 API 在智能画布中属于同一种“平台”选择，但不是同一种传输方式。运行节点只面向统一标准请求；平台适配器负责把标准请求转换成 HTTP 请求或本地 CLI 子进程调用。这样即梦 CLI 可以和 RunningHub、AI MONEY、ModelScope 等并列出现在图片、视频运行节点的平台注册表中，不需要增加“即梦专用节点”。

```text
图片/视频运行节点
→ 统一输入、参数和能力校验
→ 选择平台与模型
→ 生成平台无关标准请求
→ 即梦 CLI 适配器
→ 本地受控子进程
→ 任务 ID、轮询、结果下载
→ 统一运行记录和素材节点结果
```

#### 4.15.1 当前项目已确认的即梦 CLI 能力

当前代码已经存在即梦 CLI 的命令白名单、任务提交和查询、结果下载、登录/额度接口，以及 macOS 本地执行和 Windows WSL 执行路径。因此本次规划优先抽取和复用现有能力，不重新编写一套即梦调用链。

已确认可以进入首批能力档案的模型和操作：

| 媒体节点 | 模型范围 | 已确认操作 | 说明 |
| --- | --- | --- | --- |
| 图片生成 | `5.0Pro`、`5.0`、`4.7`、`4.6`、`4.5`、`4.1`、`4.0`、`3.1`、`3.0` | `text2image`、`image2image`、`image_upscale` | 具体输入和参数必须按 CLI 帮助、现有请求构造和实际测试逐项登记 |
| 视频生成 | `seedance2.0_vip`、`seedance2.0fast_vip`、`seedance2.0`、`seedance2.0fast`、`seedance2.0mini` | `text2video`、`image2video`、`multimodal2video`、`frames2video`、`multiframe2video` | 首帧、尾帧、多帧、视频和音频参考按模型能力档案筛选 |

上述清单只说明项目已经有对应命令和模型入口，不等于每个模型都支持表中的全部输入和参数。聊天模型、音频模型和 AI 应用不能因为即梦 CLI 存在就自动显示；只有后续得到真实 CLI 能力证据并补充档案后，才允许接入相应节点。

即梦 CLI 能力档案单独保存为 `data/model_capabilities/providers/jimeng-cli.json`，至少记录：

- `provider_id`、`model_id`、`node_type`、`operation` 和 CLI 命令。
- 文本、参考图、首帧、尾帧、视频、参考音频等输入角色及数量限制。
- 比例、分辨率、时长、生成音频、提示词增强等已经证实的参数。
- `request_mapping`：统一语义到 CLI 参数或参数文件字段的映射。
- 能力档案版本、核对日期、证据等级、来源和当前状态。

CLI 参数不能直接提升为跨平台通用参数。比如 CLI 命令中的 `--xxx` 只属于即梦适配器；只有经过语义确认后，才映射到节点中的“首帧”“时长”或其他稳定字段。

#### 4.15.2 API 设置中的 CLI 平台卡片

API 设置中增加统一的 CLI 平台卡片。界面可以聚合平台定义和本机运行状态，但持久化时必须分开。旧的 `jimeng` 标识在迁移期继续兼容，并映射到统一的 `jimeng-cli` 平台标识。

可迁移的平台定义继续保存在 `data/api_providers.json`：

```json
{
  "id": "jimeng-cli",
  "name": "即梦 CLI",
  "protocol": "jimeng",
  "transport": "local_cli",
  "enabled": true,
  "minimum_version": "1.4.2",
  "image_models": [],
  "video_models": [],
  "chat_models": [],
  "audio_models": []
}
```

当前设备的运行状态单独保存在 `data/settings/cli_runtimes.json`，不进入画布和工作流导出：

```json
{
  "jimeng-cli": {
    "executable": "dreamina",
    "use_wsl": false,
    "wsl_distro": "",
    "install_state": "unknown",
    "login_state": "unknown",
    "detected_version": "",
    "last_checked_at": 0
  }
}
```

`transport=local_cli` 是运行方式，不是模型能力。CLI 安装状态、检测版本、WSL 状态和登录状态属于本机运行环境；平台最低版本和用户启用的模型属于平台配置；模型输入和参数属于能力档案。API Key 不适用于即梦 CLI，界面不显示误导性的 API Key 输入框。登录凭据本身仍由 CLI 官方登录机制管理，`cli_runtimes.json` 只记录可公开状态，不保存 Cookie 或令牌。

CLI 平台卡片至少提供：

- 检测 CLI：检查可执行文件、版本、运行权限和 Windows WSL 环境。
- 安装/更新 CLI：执行项目内置的受控安装流程。
- 登录、检查登录状态、退出登录和查看额度。
- 查看帮助和安装/检测日志。

状态与按钮规则：

| 状态 | 用户可见结果 | 可用操作 |
| --- | --- | --- |
| 未检测 | 显示“检测 CLI” | 检测、安装/更新 |
| 未安装 | 显示安装说明 | 安装/更新、查看诊断 |
| 已安装但版本过低 | 显示当前版本和最低版本 | 更新、查看诊断；禁止运行节点提交 |
| 已安装但未登录 | 显示“需要登录” | 登录、检查状态；禁止运行节点提交 |
| 已登录且版本合格 | 显示可用 | 图片/视频运行节点可以进入能力筛选 |
| Windows 缺少 WSL 或发行版 | 显示缺少的系统条件 | 按受控流程检查或安装 WSL；不能伪装成 CLI 已可用 |
| 检测或安装失败 | 显示阶段、退出码和脱敏日志 | 重试、查看诊断；不能伪装成功 |

安装和登录操作必须由后端白名单接口触发，前端不能传入任意 Shell 文本。建议接口为：

```text
POST /api/jimeng/install
GET  /api/jimeng/status
POST /api/jimeng/login/start
GET  /api/jimeng/login/status
GET  /api/jimeng/credit
POST /api/jimeng/logout
POST /api/jimeng/help
```

安装接口返回 `install_id` 和阶段状态；前端通过状态接口轮询，不阻塞页面。后端只调用项目内置脚本或固定命令白名单：macOS 使用官方安装入口并写入本地 CLI 配置，Windows 通过受控 PowerShell/WSL 流程执行同一官方安装入口。安装前明确提示网络需求以及 Windows 可能需要管理员权限；失败时保存退出码、阶段、脱敏日志和修复建议。

#### 4.15.3 智能画布中的运行规则

图片生成节点和视频生成节点的平台列表统一包含“即梦 CLI”。用户选择后，节点按以下顺序处理：

1. 检查本机 CLI 安装状态、最低版本和登录状态。
2. 根据当前连接的文本、图片、视频、音频及其数量和角色筛选即梦操作与模型。
3. 根据能力档案显示真实支持的参数和输入槽。
4. 生成平台无关标准请求，并由即梦适配器转换为固定命令及参数。
5. 通过现有任务状态机保存提交状态、`submit_id` 或平台任务 ID，继续轮询和恢复。
6. 将平台返回结果下载到本地任务临时目录，校验后登记为稳定生成结果，再创建素材节点引用。

CLI 未安装、未登录、版本过低、输入角色不兼容或命令参数无法映射时，运行必须在本地校验阶段阻止，并显示对应处理入口；不能静默改用其他平台，也不能让用户选择了参数却在 CLI 请求中无提示地丢弃。

CLI 的本地任务也必须遵循远程任务的统一幂等和恢复规则：保存 `run_id`、`attempt_id`、本地进程状态、CLI 退出码、脱敏标准输出/错误输出、平台任务 ID和结果落地状态。提交后即使浏览器关闭，也要根据任务记录继续查询或明确进入待恢复；不能只依赖前端进程是否还存在。

#### 4.15.4 普通画布兼容与迁移边界

即梦 CLI 的命令白名单、版本检测、Windows WSL 路径处理、任务查询和结果下载作为公共平台适配器保留，由智能画布的新图片/视频运行节点调用；普通画布不再作为调用入口。

智能画布统一写入 `jimeng-cli`、`transport`、能力档案版本和运行快照。MiniMax、`smart-prompt`、`smart-loop`、`smart-group`、`smart-minimax` 以及其他历史专用节点不因 CLI 接入而改结构，只增加必要的连接和统一运行契约适配；它们不是普通画布专属代码，仍按智能画布兼容边界维护。

#### 4.15.5 CLI 的双平台要求

所有 CLI 功能必须在 macOS 和 Windows 分别完成安装、检测、登录、生成、轮询、结果落地和失败恢复验证：

- macOS 使用本地 `dreamina` 可执行文件，并允许通过 `DREAMINA_BIN` 指定路径。
- Windows 使用 WSL 执行即梦 CLI；支持 `JIMENG_USE_WSL` 和 `JIMENG_WSL_DISTRO` 配置，并处理 Windows 与 WSL 之间的路径转换。
- 画布和工作流只保存平台配置、稳定模型 ID和能力快照，不保存机器绝对路径；绝对路径只作为当前设备的运行配置。
- 安装脚本、状态文案、错误诊断和按钮在中文界面提供中文说明，同时保留 CLI、环境变量、接口路径和平台官方原文的准确拼写。
- CLI 登录凭据、Cookie、令牌和完整授权信息不写入画布、工作流导出包、普通备份或日志；需要备份时沿用现有显式敏感信息选项。

### 4.16 OpenAI Codex CLI 平台适配

项目中的“GPT CLI”实际对应 OpenAI Codex CLI。它和即梦 CLI 都属于本地 CLI 平台，但产品定位不同：即梦 CLI 是媒体生成命令集，Codex CLI 是可以在本地工作目录中执行任务的文本代理。两者都通过 API 设置配置和检测，但不能因为名称里都有 CLI 就把 Codex 的文本代理能力误当成图片、视频或音频生成能力。

#### 4.16.1 当前代码已经确认的能力

| 平台配置 | 实际调用 | 当前能力 | 智能画布归属 |
| --- | --- | --- | --- |
| `codex` | `codex exec` | 文本生成、对话、系统提示词、历史消息；当前实现可携带图片作为上下文 | `smart-text-generator`；旧 `smart-prompt` 仅兼容历史画布 |
| `codex` | 无当前适配器 | 视频生成 | 暂不接入视频节点 |
| `codex` | 无当前适配器 | 音频生成、语音合成、音乐生成 | 暂不接入音频或音乐节点 |

这里需要区分两个事实：

1. `codex exec` 本身是文本/代理执行入口，项目通过 `--image` 将图片作为上下文传入；它不是一个视频或音频生成 API。
2. 项目中即使存在 GPT Image 2 相关辅助工具，也不把它视为 GPT CLI 的图片能力；本次明确不接入 Codex 图片生成。

Codex CLI 能够通过本地代理读取、修改或转换文件，不等于它拥有媒体生成模型。例如它可以借助 FFmpeg 执行媒体处理，但这属于本地素材处理，不应在图片、视频或音频生成节点中显示为 Codex 模型能力。

#### 4.16.2 API 设置中的 GPT CLI 配置

API 设置中保留“GPT CLI”快捷添加入口，并将协议配置为 `codex`。用户不需要在本项目中填写 API Key，配置重点是：

- 本机 `codex` 是否已安装、版本是否可执行。
- 本机是否完成 Codex 登录；登录状态由首次受控执行或 CLI 自身诊断确认。
- 文本模型默认显示 `gpt-5.5`，作为本机 CLI 的默认模型入口，不承诺这是所有账号都可用的固定模型。
- 图片、视频和音频模型保持空列表，不显示“未验证但可能支持”的选项。

用户可以在 API 设置里编辑或刷新文本模型名称，但模型是否可运行仍由本机 CLI 和文本能力档案共同决定。Codex CLI 当前不应使用远程 API 的“拉取模型”逻辑伪造模型列表；默认模型来自项目适配器，实际可用性由检测和运行验证确认。

GPT CLI 卡片建议提供：

- 检测 CLI：检查 `codex` 路径、版本和基本执行能力。
- 安装/更新 CLI：调用项目内置的 macOS 或 Windows 安装脚本。
- 登录/打开登录：引导用户通过 Codex 官方登录流程完成本机认证。
- 查看帮助和诊断日志。

GPT CLI 的 macOS、Linux 和 Windows 安装脚本只安装或更新 OpenAI Codex CLI，不再安装 `gpt-image-2-skill` 或其他图片辅助包。这样安装行为、API 设置和智能画布的能力边界保持一致，避免用户误以为 GPT CLI 会出现在图片生成节点中。

状态至少区分 Codex CLI 是否安装、版本是否合格和是否已登录：

| 状态 | 画布能力 |
| --- | --- |
| 未安装 | `smart-text-generator` 的 Codex 文本能力不可运行，只显示安装入口 |
| 已安装但未完成登录 | 文本能力不可运行，显示登录入口 |
| 已安装且已登录 | `smart-text-generator` 可以选择 Codex 文本模型并执行 |
| CLI 版本或诊断异常 | 阻止文本运行，保留诊断和更新入口 |

#### 4.16.3 智能画布的映射规则

Codex 文本能力直接映射到 `smart-text-generator`：

```text
smart-text-generator
→ 平台选择：GPT CLI
→ 模型选择：gpt-5.5 或用户已验证模型
→ 系统提示词、用户提示词、Skill 和历史输入
→ codex exec
→ 文本素材节点结果
```

当前 `codex exec` 允许图片作为输入上下文，但这只属于文本任务的参考输入，不改变 Codex 作为文本平台的定位。视频和音频输入不因为文件可以被 CLI 读取就自动开放。

#### 4.16.4 是否接入图片、视频和音频

当前产品规则是不接入 Codex CLI 的图片、视频和音频生成：

- 当前项目明确不把 `gpt-image-2-skill` 归入 GPT CLI 图片能力。
- 当前项目没有 Codex 视频命令、视频任务轮询和视频结果下载适配器。
- 当前项目没有 Codex 音频生成、语音合成或音乐生成命令适配器。
- Codex 调用 FFmpeg、读取媒体文件或修改媒体文件属于素材处理，不是模型生成能力。
- 若未来接入 OpenAI 官方图片、视频或音频 API，应作为独立的远程 API 平台或独立 CLI 工具建立能力档案，不能直接挂在 Codex CLI 的空模型列表上。

只有同时满足“官方或工具文档明确支持”“当前项目有受控命令或请求实现”“任务状态和结果落地已验证”“macOS 与 Windows 均完成验证”四个条件，才可以把对应能力标记为 `confirmed` 并显示在智能画布节点里。

#### 4.16.5 Codex CLI 的安装与安全边界

GPT CLI 的安装流程与即梦 CLI 同级，但脚本和环境不能混用：

- macOS 使用 `CLI/macos/openai/install_openai_codex_cli.command`。
- Windows 使用 `CLI/windows/openai/1-install_openai_codex_cli.bat` 及其 PowerShell 安装脚本。
- 前端不能提交任意安装命令；后端只允许调用固定脚本、固定参数和固定子命令。
- `codex exec` 必须使用参数列表启动子进程，设置工作目录、超时和输出文件；禁止拼接用户文本执行 Shell。
- 用户提示词、Skill 正文、图片路径和任务输出写日志前必须脱敏；不得记录登录凭据、Cookie、API Key或完整本地授权文件。
- 工作流导出只保存 `codex` 平台、模型 ID、能力档案版本和非敏感参数，不保存 `CODEX_BIN`、辅助工具路径或本机登录状态。

### 4.17 自定义平台 Provider Manifest

自定义平台的目标不是允许用户直接修改画布节点，而是把“平台文档如何调用”转换成画布已经理解的标准能力。画布节点、统一任务语义和标准请求保持稳定；新增平台只补充目录解析、能力档案和请求适配。

#### 4.17.1 接入边界

- 官方维护平台的 Manifest 和适配器由项目维护，普通用户只配置凭据、站点或 CLI 登录。
- 用户添加的自定义平台由添加者维护。项目提供格式、校验器、调试结果和升级说明，但不承诺第三方模型长期兼容。
- 自定义平台不得新增私有画布节点字段、修改共用连接语义或覆盖官方能力档案。确有新能力时，先扩展统一语义词典，再由节点消费。
- Antigravity CLI 与以后用户自行添加的平台统一走该入口，不纳入官方平台完成度。

#### 4.17.2 Manifest 结构

Provider Manifest 至少包含：

| 区域 | 内容 |
| --- | --- |
| `provider` | 稳定平台 ID、中英文名称、版本、维护者、文档来源 |
| `transport` | `http` 或 `local_cli`、Base URL、允许的协议和超时 |
| `auth` | Key 所在请求头或查询字段；只描述位置，不保存真实密钥 |
| `catalog` | 模型目录 endpoint、分页、字段解析和输出类型校正规则 |
| `families` | 用户可见模型家族、任务变体和真实模型 ID |
| `capabilities` | 输入类型、角色、数量、参数、依赖、输出和证据 |
| `adapter` | 标准请求到平台字段的声明式映射、上传规则和内容类型 |
| `task_protocol` | 同步或异步提交、状态查询、取消和结果解析 |
| `errors` | 平台错误码到统一错误层级的映射 |
| `security` | 允许的域名、重定向、上传目标和敏感字段脱敏规则 |

只有字段重命名、嵌套路径、枚举转换和简单条件可以使用声明式映射。需要签名算法、复杂上传或特殊轮询时，使用项目审核过的受控适配器插件；Manifest 不允许内嵌任意 JavaScript、Python、Shell 或可执行模板。

#### 4.17.3 AI 辅助转换流程

用户可以把本项目的接入规范与目标平台官方 API 文档一起交给 AI，生成 Provider Manifest 草稿。AI 只能减少人工抄写，不能替代接口证据或验证：

```text
读取本项目统一语义和 Manifest Schema
→ 读取目标平台官方文档
→ 生成带来源引用的 Manifest 草稿
→ JSON Schema 校验
→ 语义和家族/变体引用校验
→ 域名、重定向和 SSRF 安全检查
→ 目录解析夹具测试
→ 标准请求到平台请求的快照测试
→ 用户确认后启用
```

文档没有说明的字段必须标为 `unknown`，不能让 AI 按同类模型经验补全。连接测试成功只证明地址、认证或目录接口可达；没有真实生成授权时，状态只能到 `contract_validated`，不能标为 `runtime_verified`。

#### 4.17.3.1 面向用户的交付方式

API 设置的“新增平台”区域必须提供三项入口：本接入规范、Provider Manifest Schema 和自动生成的 Agent 指令，并明确显示项目内路径 `docs/第三方API平台接入规范.md` 与 `data/model_capabilities/provider-manifest.schema.json`。用户不需要修改画布节点代码；只需将这三项内容与第三方官方文档交给本地 Agent，完成适配后回到 API 设置填写自己的凭据、拉取自己的目录和选择自己的模型。页面提示必须明确三步：先让 Agent 做本地适配和 dry-run，再由用户填写 Key 并拉取目录，最后由用户按文本/图片/视频/音频选择启用模型。该流程让用户能够维护自己的平台，同时保留画布稳定语义、凭据隔离和模型启用边界。

这里的“自定义平台”是项目级适配能力和用户级运行配置的分离：Manifest、能力档案、受控适配器和契约测试属于当前项目代码；API Key、目录快照、四类启用清单和平台开关属于当前用户。一个用户配置完成后，不会自动让其他用户获得其 Key、目录或启用状态；其他用户必须在自己的项目中完成适配并填写自己的凭据。用户拉取全部模型后，可以按文本、图片、视频、音频分类删除或停用不需要的模型，画布只投影当前用户仍启用且 `readiness=ready` 的模型。停用是用户级投影操作，不是删除平台能力；历史节点继续保留原模型快照，但在模型停用或档案失效时必须阻止再次运行并要求重新选择。

#### 4.17.3.2 第三方字段映射契约

第三方文档到画布之间必须存在平台无关的标准请求层。Agent 先根据官方证据填写“官方字段 → 标准字段 → 画布位置 → 平台字段”的映射，再实现 Manifest 或受控适配器。标准层至少固定平台、模型家族、任务变体、真实模型 ID、节点类型、操作模式、输入媒体类型/角色/数量/顺序、有效参数、能力档案版本和请求映射版本；第三方 `input2`、`image_url`、`frames`、`task_id` 等字段不得直接成为画布字段。

映射验收按五层执行：目录发现可解析，模型家族和任务变体可归并，输入角色与数量可校验，动态参数可按官方类型和提交值渲染，提交/查询/取消/结果/错误可生成本地请求快照。文档没有证据的字段标记为 `unknown` 或 `needs_profile`，不生成可运行控件；同一家族的文生、图生、首尾帧、多图参考、编辑和延长等能力必须作为独立变体路由，不能仅按模型名称猜测。

#### 4.17.3.3 规范迭代与实操校准

本规范按“初版 → 已验证差异 → 修订版”迭代。每完成一个平台的本地 dry-run，就记录官方 Schema、标准请求、平台请求快照、参数界面和错误映射之间的差异；只有确认差异属于公共语义时才扩展词典、Schema 或标准请求，平台专属行为继续留在受控适配器。未获真实生成授权时，所有结果只能标记 `contract_validated`，不得将理论映射或目录拉取写成 `runtime_verified`。

#### 4.17.4 兼容与升级

Manifest 需要独立版本和最低画布协议版本。更新前保存旧版并计算模型家族、变体、参数和 endpoint 差异；Schema 校验失败时继续使用最近有效版本。历史画布保存当时的 Manifest/能力快照，平台升级不得让历史请求被新映射重新解释。

当前项目已有六个平台的接入方式应先按同一结构实操：本轮完成 ModelScope、RunningHub、AI MONEY、即梦 CLI 和 GPT CLI 的抽象验证，火山引擎延期。这样自定义接口来自已验证的共同结构，而不是先设计一份脱离现有调用器的理想化格式。规范先作为可执行初版使用；每接入一个真实平台，就用官方 Schema、请求快照、错误映射和参数展示进行反向校准，发现理论与实际不一致时先更新规范或 Schema，再更新适配器和测试，不把初版当成不可修改的最终协议。

## 五、提示词库与 Skill 库

### 5.1 提示词库

保留现有“系统提示词库”和用户自建提示词库。提示词模板是结构化、可直接编辑的固定文本，可用于：

- `smart-text-generator` 或历史提示词节点的用户提示词、系统提示词；文本生成输出进入素材节点的文本 `result` 状态。
- 图片和视频节点的生成提示词。
- 图片和视频节点的提示词优化指令。

### 5.2 Skill 库

在提示词素材管理中增加与“系统提示词库”同级的“Skill 库”。

首批要求：

- 支持导入 `.md` Markdown 文件。
- 保存 Skill 名称、说明、原文件名、正文、更新时间和稳定 ID。
- 支持预览、编辑名称、替换文件、删除和分类。
- 运行节点加载 Skill 时，将 Skill 正文作为系统能力上下文使用。
- 同一节点保存所选 Skill 的稳定 ID和运行时内容快照；Skill 更新后历史节点继续使用旧快照，用户主动“更新到最新版”后，后续运行才写入新快照。

Skill 在不同节点中的用途：

- 文本节点：约束文本模型的角色、流程、格式和专业能力。
- 图片或视频节点：约束提示词优化模型如何分析并改写提示词。
- 后续音频节点：可用于歌词、配音、音乐风格或发音规则等任务。

## 六、循环节点适配

循环不分别写进文本、图片、视频、音频、音乐和 AI 应用节点内部，而是由六类运行节点共同实现统一执行接口，现有循环节点调用这个接口。历史提示词节点不因本次拆分改造成新的循环运行节点。

统一执行接口至少包含：

```text
读取当前输入
应用本轮变量
校验模型兼容性
提交一次运行
等待或登记异步任务
生成结果记录
返回本轮输出
```

循环节点负责：

- 循环次数和起始编号。
- 串行或并发。
- 每轮提示词或变量。
- 素材批次和组合规则。
- 每轮生成数量。
- 失败后停止、跳过或重试策略。
- 素材节点的轮次编号和排列。

### 6.1 循环打组规则

- 循环节点默认将本次循环产生的所有素材节点组织为一个结果组。
- 每一轮仍然保留独立的素材节点和结果记录，结果组只是上层引用结构。
- 一轮内生成多个同类型结果时，不拆成多个轮次；多项结果保留在该轮素材节点中。若一轮返回多种媒体，则该轮使用组合结果组承载不同类型的素材节点。
- 循环结果组可以直接连接到文本、图片、视频、音频、音乐或 AI 应用运行节点，也可以继续连接历史提示词节点；文本运行节点输出仍固定为文本结果。
- 连接到运行节点时，用户可以选择按轮次、按结果项或单项展开。
- 循环组可以继续作为另一个循环节点的输入，外层循环不得破坏内层轮次和结果项的稳定编号。
- 结果组中的某一项被单独拖出时，只创建引用节点，不复制实际文件。
- 重新运行循环时生成新的结果组，不覆盖旧结果组；旧结果仍可在画布和素材库中使用。

这样六类新运行节点只需要实现同一个执行契约，不需要分别复制一套循环代码；历史提示词节点沿用原有执行逻辑。

### 6.2 循环并发、规模和停止规则

循环默认使用串行执行。用户可以主动开启并发，但必须明确选择最大并发数；系统还要叠加平台级并发上限，最终采用两者中较小的限制。默认串行不是为了降低能力，而是为了避免平台限流、重复计费、结果顺序混乱和本地瞬时资源占用过高。

运行前必须展示本次执行规模：循环轮数、每轮模型调用次数、模型单次输出数量、预计总调用次数和预计结果数。超过产品安全阈值时要求用户再次确认，不能因为结果组继续连接外层循环而静默形成指数级调用。

- 用户点击停止后，立即停止提交尚未开始的新轮次；已经提交到平台的任务进入“取消中”或“等待已提交结果”，不能伪装成从未运行。
- 平台支持取消接口时尝试取消，并保存平台返回状态；平台不支持取消时明确提示可能仍会产生结果或费用。
- 循环重试默认只重试失败项，不重复提交已经成功的轮次和结果项。
- 单轮失败策略支持停止、跳过和有限次数重试；重试次数必须有上限，并使用新的 `attempt_id` 归属于原 `run_id`。
- 循环的最终状态可以是成功、部分成功、失败或已取消；部分成功时已经落地的结果继续可用，不能因其他轮次失败而删除。
- 并发执行不改变轮次编号和结果顺序，界面按预先确定的轮次位置归档，而不是按平台返回先后顺序重排。

## 七、运行时一致性与故障恢复

六类新运行节点、历史提示词节点的文本结果兼容层，以及循环驱动的新节点，都必须使用统一运行记录。前端节点状态只负责展示，后端运行记录才是任务状态和恢复判断的事实来源。

### 7.1 统一任务状态机

```text
draft（草稿）
→ validated（已验证）
→ queued（排队中）
→ submitted（已提交）
→ processing（处理中）
→ succeeded（成功）
```

任何已提交任务还可以进入：

```text
partially_succeeded（部分成功）
failed（失败）
cancelling（取消中）
cancelled（已取消）
expired（已过期）
recoverable（待恢复）
```

- `validated` 之前完成输入、能力档案、参数、连接和平台配置校验，校验失败不能生成平台任务。
- 获得平台任务 ID 后立即进入 `submitted` 并持久化，不等待首次轮询成功才保存。
- 浏览器关闭、刷新或本地服务重启后，根据后端运行记录和 `provider_task_id` 继续轮询；节点不能只依赖内存中的 `running=true`。
- 平台已接受任务但暂时无法查询时进入 `recoverable`，保留恢复入口和最后一次错误，不自动当作失败重新提交。
- 一次运行返回多项结果时允许 `partially_succeeded`；成功项先落地并可用，失败项保留错误和重试入口。
- 状态变化必须记录时间、原因和来源，禁止从终态无解释地回到处理中。
- 本地 CLI 任务除统一状态外，还要记录本地子进程状态、退出码、脱敏标准输出/错误输出、平台任务 ID和安装环境快照；子进程异常退出不能直接覆盖已经提交的平台任务状态。

### 7.2 幂等、防重复提交与重试

每次运行至少保存：

```text
run_id
attempt_id
idempotency_key
provider_task_id
provider_id
model_id
submitted_at
last_polled_at
```

`run_id` 表示用户的一次业务运行，`attempt_id` 表示该运行的某次实际提交。相同节点、相同输入快照和相同参数在同一次用户操作中只能产生一个幂等键；重复点击、网络超时、页面刷新和恢复轮询必须优先查找原任务，不能直接再次调用平台。

“继续查询”只恢复原 `provider_task_id`，不产生新的平台提交。“重试失败项”创建新的 `attempt_id`，但仍属于原 `run_id`，并只处理没有成功落地的结果。“重新生成全部”视为新的 `run_id`，界面必须提示这可能产生新的计费。

平台原生支持幂等请求头或请求字段时必须使用；平台不支持时，由本地运行记录、提交锁和幂等键阻止并发重复提交。任何错误提示都要说明平台任务是否已经创建，以及再次操作是否可能产生新费用。

### 7.3 运行输入与能力快照

每次提交前冻结一份可追溯快照，至少包含：

- 输入素材 ID、结果 ID、物理内容 SHA-256、用户可见名称、媒体类型、输入角色和顺序。
- 用户提示词、系统提示词、Skill 稳定 ID和内容快照、模板快照。
- 平台、模型、操作模式、能力档案版本和当前平台动态字段快照。
- 最终有效参数、被判定为不适用而未发送的草稿参数，以及平台请求映射版本。
- 来源画布、运行节点、循环节点、轮次、批次和父结果组关系。

运行中的素材即使后来改名、晋升分类或在别处被编辑，也不改变本次运行快照。改变媒体内容的操作必须产生新的素材或结果 ID，不能在原 ID下替换文件。历史结果展示使用运行快照解释来源，不用当前最新设置反推过去。

### 7.4 远程结果本地化和部分落地

平台返回 URL、Base64、文件流或平台素材 ID后，都必须转换为本地稳定结果：

```text
识别平台结果
→ 下载或解码到任务临时目录
→ 校验内容类型、扩展名、文件大小和可读性
→ 计算 SHA-256 并复用物理内容
→ 写入逻辑结果记录
→ 原子更新结果索引
→ 画布引用本地稳定结果 URL
```

平台的临时签名 URL不能直接作为永久结果保存。下载或校验失败时，结果项进入“待落地”或失败状态，保留远端追踪信息和重试下载入口；只有本地文件和结果索引都写入成功后，才能标记该结果项成功。

多结果任务逐项落地。已经成功落地的结果不因其他结果失败而回滚或删除；重新下载失败项不能重新提交模型任务，除非远端结果已经不可恢复且用户明确选择重新生成。

### 7.5 连线和图结构运行前校验

保存和运行前都要校验图结构：

- 节点 ID、连接 ID和连接两端必须存在且唯一。
- 输入端口的媒体类型、数量和角色必须符合当前能力档案。
- 单值端口不得同时接收多个未分配角色的连接；多值端口必须保存稳定顺序。
- 首帧、尾帧、参考图、遮罩、待编辑视频和参考音频等角色必须显式保存，不能仅依赖连线创建顺序猜测。
- 结果组整体输入必须明确按轮次、按结果项或单项展开；接收节点不支持组输入时阻止运行。
- 普通运行节点之间禁止形成执行环；只有现有循环节点定义的受控循环可以重复执行，并必须受轮数和停止条件限制。
- 引用已删除、待落地、损坏或媒体类型不符的素材时，指出具体节点和结果，不允许提交残缺请求。

前端使用同一套规则即时提示，后端在提交前再次校验，避免手工修改画布 JSON 或前端状态不同步绕过约束。

### 7.6 错误分类、诊断和脱敏

错误至少分为输入不完整、能力不兼容、参数无效、素材上传失败、平台认证失败、平台限流、平台任务失败、轮询暂时中断、结果下载失败、本地落盘失败和画布保存失败。界面显示用户能理解的中文说明，同时保留平台、模型、`run_id`、`attempt_id`、平台任务是否已创建、是否可以安全重试和重试是否可能再次计费。

平台返回非 JSON、HTML 错误页或纯文本错误时，先按 HTTP 状态和 `Content-Type` 解析，再生成统一错误对象；不能直接调用 JSON 解析后只显示 `Unexpected token`。日志严禁输出完整 API Key、Authorization、Cookie、签名 URL查询参数、Skill 私密正文和用户素材内容。

### 7.7 大画布性能和运行资源上限

素材节点、结果组和历史记录可能持续增长，界面不能因为结果数量增加而一次性加载全部原文件。画布默认使用缩略图、视频首帧、音频波形摘要和文本摘要；只有节点进入可视区域、用户展开详情或开始播放时，才加载对应原媒体。折叠结果组只渲染摘要和可见项，展开大组时使用分段或虚拟列表。

任务轮询由统一调度器管理，不能让每个节点各自建立无限 `setInterval`。调度器按平台和任务状态合并轮询、使用合理退避，并在页面不可见时降低只读轮询频率；正在上传、取消或即将完成的任务仍保持必要更新。页面恢复可见时先从后端运行记录同步，不根据前端旧计时器猜测状态。

自动保存使用防抖和变更批次，但运行状态、平台任务 ID和结果落地属于关键写入，必须立即持久化。大量媒体解码、本地处理和结果下载都受独立并发上限控制，避免占满浏览器内存、Python 线程或磁盘带宽。达到容量、文件大小、运行数量或剩余磁盘阈值时，在提交前阻止新增任务并说明处理建议。

## 八、双击编辑窗口

六类新运行节点均采用“画布节点摘要 + 双击完整编辑窗口”的两层结构。历史提示词节点继续使用自己的现有交互，不在本次拆分中改成这一套新窗口。

节点摘要显示：

- 节点类型。
- 当前平台和模型或 AI 应用名称。
- 当前操作标签。
- 关键参数摘要。
- 输入数量和兼容状态。
- 最近一次运行状态和最近结果预览。

双击窗口显示：

- 完整输入映射。
- 提示词编辑。
- 平台、模型和操作选择。
- 模型能力允许的全部参数。
- Skill 和提示词模板。
- 历史运行记录和最近结果。
- 运行前错误和缺失输入提示。

常用参数在第一层直接展示，高级或低频参数放入明确标注的“更多参数”，避免窗口过度拥挤。

## 九、素材库入口

画布右上角入口统一命名为“素材库”，不得再叫“资产库”。面板包含：

- 资产素材。
- 临时素材。
- 生成结果。

生成结果继续支持按全部、图片、视频、音频、文本筛选，并按来源画布分区。任何素材或结果拖到画布后，都创建引用节点，不复制磁盘文件。

## 十、数据兼容与迁移

- 现有智能画布 JSON 必须能够被迁移器读取并转换。
- 旧 `smart-image` 混合节点需要通过迁移器判断其角色，转换为素材节点、图片/视频/音频/AI 应用运行节点，或将已有结果登记为素材节点的 `result` 状态；迁移成功后旧节点从画布节点列表中移除。
- `smart-prompt`、`smart-loop`、`smart-group` 和 `smart-minimax` 不属于本次迁移对象，继续保持现有节点类型、界面、交互和数据结构。
- 迁移前必须生成可恢复备份；迁移过程可重复执行，并使用迁移标记避免重复创建节点和结果。
- 无法自动判断的内容不能静默丢弃：应进入迁移报告和隔离数据区，阻止本次迁移提交，等待适配规则补齐；正常画布中不得继续显示一个未迁移的旧节点。
- 新增数据字段必须同时兼容 macOS 和 Windows 路径及编码。
- 用户界面新增文案必须同步维护中文和英文。
- 迁移层至少包含旧节点解析器、旧连接语义转换器、旧运行设置适配器和旧结果登记器；这些组件只服务旧数据导入、备份恢复和迁移测试。
- 读取旧画布时先在内存中生成新结构并展示迁移报告；迁移成功后写入新结构，旧 JSON 只保留在备份中，不再作为正常运行数据读取。
- 迁移必须先对当前真实智能画布样本做副本验证，重点覆盖 `smart-image` 的素材、`runSettings`、结果和相关连接；其他节点 JSON 必须保持不变。
- `smart-group` 不迁移为结果组；结果组使用独立的新节点类型实现。历史结果关系如果原来依附 `smart-image`，只迁移对应结果引用和连接。
- 迁移 `smart-image` 及其连接时，必须保留其他所有现有节点原始数据，并把相关连接正确映射到拆分后的新节点。

### 10.1 素材删除、回收站和断链处理

删除画布节点、删除素材库记录和物理删除文件是三种不同操作：

- 从画布移除素材节点只删除 `node_id` 和相关连线，不删除素材、结果或物理文件。
- 从结果组移出单项只删除组内引用，不删除结果项。
- 在素材库删除素材或结果前，系统必须统计画布节点、结果组、运行快照和运行中任务的引用。
- 存在运行中任务引用时禁止物理删除；用户应先停止任务，或等待任务进入终态。
- 存在画布或结果组引用时，默认不直接物理删除，先说明被哪些画布和结果使用。用户确认强制删除后，记录进入回收站，原画布节点保留并显示“素材已删除”，不能静默移除节点或连线。
- 回收站保留稳定 ID、原路径、哈希和引用摘要；恢复后原画布引用自动重新可用。
- 回收站到期清理时，只删除引用计数为零、没有运行中任务且不再被历史结果依赖的物理内容。
- 物理文件缺失、索引损坏或用户从文件系统手动删除时，界面显示断链状态并提供重新定位、从备份恢复或移除引用，不在运行时返回空白素材。

### 10.2 画布保存原子性和版本冲突

每个新版智能画布必须保存 `schema_version`、递增 `revision`、`updated_at` 和最近一次成功迁移版本。保存流程固定为：校验画布结构，写入同目录临时文件，刷新文件内容，原子替换正式 JSON；写入失败时保留上一份完整画布，不能留下半截 JSON。

客户端保存时携带它读取到的基础 `revision`。服务端发现基础版本落后时，不允许直接覆盖；先按节点、连线和运行记录进行现有冲突合并，无法安全合并的同字段修改必须提示用户选择。任务状态、已落地结果和结果引用采用并集保护，不能因旧窗口保存而丢失。

加载画布时先校验 JSON、Schema 和索引引用。正式文件损坏时尝试读取最近一次有效备份或恢复点，并生成诊断报告；恢复动作必须由用户确认后覆盖正式文件。画布自动保存和运行状态写入不能互相覆盖，后端使用统一写锁和原子写入工具。

当前实现已经完成画布 JSON 的同目录临时写入、`fsync` 刷盘、`os.replace` 原子替换和递增 `revision`。智能画布及轻量元数据修改都提交 `base_revision`，服务端在同一写锁内校验并拒绝旧版本，`base_updated_at` 只保留给旧客户端兼容；素材重命名等关联更新也必须经过统一画布保存入口。尚未完成的是节点、连线和统一运行记录的字段级冲突合并，以及任务状态、已落地结果和结果引用的并集保护。

### 10.3 工作流导入导出和资源包

工作流导出提供两种明确模式：

1. 仅画布结构：导出节点、连线、能力档案版本、素材 ID和结果 ID，不包含实际媒体文件。适合同一项目内复用。
2. 包含引用资源：在结构文件之外打包选中节点实际引用的素材、结果、必要预览和能力档案快照，不包含 API Key、Cookie、本机绝对路径或可恢复的缓存。

导入资源包时先校验包格式、路径安全、清单和内容哈希；相同 SHA-256 复用已有物理内容，不重复复制。缺少资源时先给出缺失清单和受影响节点，允许用户重新定位或以断链状态导入，但不能把缺失资源伪装成导入成功。跨 macOS 和 Windows 导入只使用项目相对路径和稳定 ID，禁止把源电脑绝对路径写入目标画布。

导出的运行节点保留平台、模型和能力档案版本，但不导出密钥。目标环境没有对应平台、模型或能力档案时，节点以不可运行状态打开并说明缺口，不自动替换模型。

CLI 节点导出时只保留 `jimeng-cli` 平台标识、模型 ID、操作模式、能力档案版本和不含敏感信息的参数快照，不导出 `DREAMINA_BIN`、WSL 绝对路径、登录状态令牌或本机安装日志。导入到另一台 macOS 或 Windows 设备后，节点先显示“需要检查本机即梦 CLI”，用户完成检测、安装和登录后才恢复可运行；不能因为源设备可用就假设目标设备也已安装。

### 10.4 外部工具、缓存和任务临时文件

视频裁剪、音频裁剪、视频抽音频、波形生成和部分格式转换依赖 FFmpeg。应用启动或首次使用相关功能时检查可执行文件和版本；macOS 与 Windows 分别使用项目配置或跨平台可执行文件查找，不假设系统一定安装了 `ffmpeg`。

FFmpeg 不可用时，浏览器能够原生完成的播放和预览继续使用；依赖 FFmpeg 的按钮显示不可用原因和安装检查入口，不能点击后才返回模糊失败。处理任务保存输入路径、命令参数摘要、退出码和脱敏后的错误输出，方便判断是环境缺失、格式不支持还是素材损坏。

资源生命周期分为：

- 原始输入素材和成功生成结果：用户数据，不自动清理。
- 缩略图、视频首帧、音频波形、转码预览：可重建缓存，放入 `cache/`，可以按容量和最近使用时间清理。
- 平台下载中间文件、上传副本和本地处理临时文件：放入任务临时目录，成功落地后清理；失败任务保留有限时间供恢复和诊断。
- 正在运行、待恢复或待落地任务的临时文件：禁止清理。
- `.pending` 和孤立临时文件：服务启动后按运行记录核对，只清理没有活跃任务引用且超过保留期的项目。

备份默认包含结构化数据、原始输入素材和生成结果，不包含可重建缓存和已完成任务临时文件；包含密钥仍必须使用现有显式选项。

即梦 CLI 的安装日志和子进程诊断日志属于本机运行诊断，不属于画布数据。日志可以保留有限时间，但必须脱敏并排除 Cookie、令牌、API Key、签名 URL和用户素材正文；安装失败或任务失败时优先保留阶段、退出码和可执行文件检测结果，方便 macOS 与 Windows 分别定位环境问题。

### 10.5 媒体安全、远程下载和索引自检

上传和远程结果不能只根据文件扩展名判断类型。系统要结合文件头、MIME、可解码性和平台声明识别真实媒体类型，并设置单文件大小、总下载量、请求超时、重定向次数和解压后大小上限。类型不符、内容损坏或超过限制时进入隔离状态，不写入正式素材或结果索引。

服务端下载远程结果时只允许平台响应或可信任务记录中产生的 URL，并阻止本机地址、局域网地址、文件协议、异常端口和重定向到不可信目标，避免远程 URL被利用读取本地服务。签名 URL只用于本次下载，不写入普通日志和长期画布数据。

文件写入和索引更新不是同一个物理动作，启动时和数据维护工具中必须提供一致性自检：发现“文件存在但索引缺失”“索引存在但文件缺失”“临时文件已完成但未提交”“哈希与索引不一致”时生成报告，并根据运行记录自动补登记、恢复待落地状态或进入隔离区；不能直接删除无法判断归属的文件。

## 十三、验证边界与延期项

- 当前不使用 AI MONEY Key，也不发起付费视频、音频或音乐生成；因此相关真实生成验收属于有意延期，不应标记为完成或接口故障。
- RunningHub 图片请求已到达上游但因钱包余额不足返回 `errorCode: 1620`；只能证明认证、协议和路由到达，不能证明成功结果落地。
- GPT CLI 文本和隔离 OpenAI 兼容平台的文本、图片链路已有成功验证，但不能据此推断其他平台或模型已经完成适配。
- 新增任何模型仍必须根据官方接口文档、官方 Schema 或经过验证的项目请求补充能力档案，不在节点代码中临时硬编码未经验证的参数。
