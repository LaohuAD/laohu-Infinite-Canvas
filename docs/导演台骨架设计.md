# 智能画布视频导演台骨架设计

## 一、目标与边界

导演台用于按照时间顺序组织、生成和预览一组视频片段。它不是剪辑软件，不承担字幕、配乐、转场、多层合成或最终成片剪辑。用户在导演台中完成镜头级视频生成后，将各个片段导入剪映或其他剪辑软件继续制作。

本设计建立一套共享导演台骨架，并提供两个产品入口：

- **通用导演台**：调用现有标准视频模型 API，复用普通视频生成节点的平台、模型、运行模式、动态参数、预检、提交、轮询、恢复和日志能力。
- **个性化导演台**：调用用户自行搭建的本地 ComfyUI 工作流、RunningHub 工作流或 RunningHub AI 应用。`MiniMax H3 导演台` 是首个个性化导演台。

两个入口的工程、素材库、Clip、时间线、预览、结果版本和导出结构完全相同，只替换生成适配器和参数面板内容。所有导演台只生成视频。

第一阶段明确不做：

- 角色与音色自动绑定；该能力只保留后续设计记录，不进入当前数据结构、界面和请求。
- 字幕、背景音乐编排、转场、视频特效和多层视频合成。
- 根据人物外观自动识别角色。
- 自动把相邻普通 Clip 建立为隐藏生成依赖。
- 复制外部 GPL 插件代码；只参考公开交互概念并按本项目架构独立实现。

## 二、现状依据与取舍

### 2.1 本项目已有能力

现有 `smart-minimax` 已具备大型工作台布局、素材库、顶部预览、普通分段、播放头、提示词、图片/视频/音频参考、分段结果版本、ComfyUI/RunningHub 运行和视频导出。现有普通视频生成节点已经具备模型能力档案驱动的候选筛选、运行模式、动态参数、运行前预检、任务提交和结果归一化。

因此不重新实现第三套视频执行逻辑。导演台 Clip 必须调用与普通视频节点相同的后端执行契约；个性化导演台通过独立适配器把同一 Clip 契约映射到工作流或 AI 应用字段。

### 2.2 外部项目可借鉴内容

`ComfyUI-MiniMaxH3-TimelineDirector` 中值得借鉴的是：用可移动生成区间决定本轮参考素材、按真实重叠范围裁取视频、通过固定 Guide/可编辑参考/边界参考区分输入作用、使用低清代理预览并把时间线状态序列化。

不直接继承其模型绑定、ComfyUI DOM Widget、节点输入输出和编码器耦合。本项目需要支持标准 API 与自定义工作流两种后端，也必须遵守现有素材索引、能力档案、画布保存和跨平台规则。

其他公开项目提供了三点补充证据：

- ComfyTV 将“时间线编辑决定”与“执行渲染”分开，说明时间线 JSON 应是独立、稳定的数据契约。
- H3 Studio 使用全屏工作区、关键帧和结果 Reel，说明复杂时间线不适合压缩成普通节点小表单。
- Sonder Editor 把项目素材、生成区间、结果版本和批量任务放在同一工程中，说明长视频创作需要工程级状态，而不是一串互不认识的单次节点。

## 三、产品入口与共享架构

```text
导演台共享核心
├── 工程名称与导演台类型
├── 工程素材库
├── 顶部固定预览区
├── 单条时间轨道
│   ├── 普通 Clip
│   └── 覆盖在普通 Clip 上的连接 Clip
├── 当前 Clip 的垂直输入清单
├── 当前 Clip 提示词与信息提示
├── 当前 Clip 动态参数面板
├── 播放头、黑场与结果版本
├── 分片导出与清单
└── 保存、恢复、撤销、日志

生成适配器
├── standard-video：现有视频模型 API
├── comfy-workflow：本地 ComfyUI 工作流
├── runninghub-workflow：RunningHub 工作流兼容入口
└── runninghub-app：RunningHub AI 应用
```

节点创建菜单分别显示“通用导演台”和“MiniMax H3 导演台”。视觉标题、生成来源说明和参数面板不同，但两者使用同一个导演台渲染器和数据归一化器。

## 四、整体布局

```text
┌────────────────────────────────────────────────────┐
│ 工程名  导演台类型  播放  运行当前  批量运行  分片导出 │
├──────────┬─────────────────────────────────────────┤
│          │              顶部固定预览区              │
│ 工程     │ 当前 Clip 结果 / 空占位 / 运行或失败状态   │
│ 素材库   ├─────────────────────────────────────────┤
│          │ 单条时间轨道：普通 Clip 与连接 Clip 同轨覆盖 │
│ 图片     ├──────────────────────┬──────────────────┤
│ 视频     │ 当前 Clip 输入与提示信息 │ 当前 Clip 生成参数 │
│ 音频     │ 素材在 Clip 下方垂直罗列 │ 动态能力驱动       │
│ 文本     │                      │                  │
└──────────┴──────────────────────┴──────────────────┘
```

顶部预览区始终固定，不随当前 Clip 类型移动。点击任何 Clip 后，预览区、垂直输入区、提示信息和右下参数面板同时切换到该 Clip。未生成时显示结果占位；运行中、失败和取消状态都在原 Clip 内表达。

## 五、素材进入导演台

素材引用使用全画布稳定素材 ID，不复制文件。

### 5.1 画布连线

画布上的文本、图片、视频和音频素材节点通过连接线接入导演台时，只进入工程素材库。连线没有目标 Clip 语义，不得猜测或自动分配。

### 5.2 从资产库拖入

- 拖到导演台素材库：只加入工程素材库。
- 直接拖到某个 Clip：加入该 Clip，同时自动登记进工程素材库。
- 从导演台素材库拖到某个 Clip：只建立 Clip 引用，不复制素材。

删除工程素材前，如果仍被 Clip 引用，必须提示受影响 Clip；不能留下失效引用。

## 六、Clip 数据模型

所有普通 Clip 和连接 Clip 都属于同一个 `clips` 集合、同一条时间轨道：

```text
DirectorClip
├── id
├── type: ordinary | connection
├── startMs（整数毫秒）
├── durationMs（整数毫秒）
├── prompt
├── inputRefs[] / refItems[]（稳定素材引用；兼容层归一化为同一来源）
│   ├── id / assetId
│   ├── kind: text | image | video | audio
│   ├── role
│   ├── url / text
│   └── name
├── generation
│   ├── providerId
│   ├── model
│   ├── mode
│   ├── params（当前模型参数）
│   └── parameterDrafts（按模型保留的参数草稿）
├── timelineInputs[]（仅连接 Clip 的只读推导输入）
├── results[]
├── currentResultId
├── result（当前结果兼容视图）
├── running / runRef（每个 Clip 独立）
└── runtimeTimelineRefs（仅运行时存在，保存前可重建）
```

时间值在数据层使用整数毫秒；模型要求帧对齐时，由适配器按模型帧率转换。拖动、缩放和 `1 秒`判断不能使用屏幕像素作为真实时间。

## 七、普通 Clip

普通 Clip 是嵌入导演台的完整视频生成节点：

- 时间宽度等于生成时长。
- 可以移动、排序和调整时长，不强制与相邻 Clip 吸附。
- Clip 之间允许空白；连续预览到空白区时显示黑画面。
- 每个 Clip 独立保存提示词、输入、模型、运行模式、参数、结果版本和运行记录。
- 新建 Clip 是空白结果占位；生成成功后在原位置显示当前结果缩略图。
- 重新生成新增结果版本，不覆盖旧结果。

### 7.1 垂直输入清单

当前 Clip 的全部素材必须位于该 Clip 下方的输入区域中垂直罗列，不使用横向缩略卡片带：

```text
文本
  @文本1  文稿名称
图片
  @图片1  角色正面.png
  @图片2  场景参考.png
视频
  @视频1  动作参考.mp4
音频
  @音频1  对白参考.wav
```

同类素材按显示顺序形成稳定编号。排序后，界面编号、提示词 `@引用` 和真实请求顺序同步更新。删除仍被提示词引用的素材前必须明确提醒。

当某种素材可能映射到多个模型输入角色时，拖入后打开锚定落点的用途选择器，例如首帧、尾帧、参考图、参考视频、音频驱动。只有一个明确角色时自动放入。

## 八、连接 Clip

连接 Clip 也是完整的嵌入式视频生成节点，不使用全局默认连接模型。它与普通 Clip 位于同一条时间轨道，使用更高层级的半透明蓝色卡片覆盖普通 Clip 和空白区，不新增第二条轨道。

连接 Clip 的时间位置自动决定锁定输入和候选模型。

### 8.1 左端规则

- 与上一个普通 Clip 尾部重叠 `< 1000ms`：自动缩减到边界，只取得上一个 Clip 当前结果的尾帧。
- 与上一个普通 Clip 尾部重叠 `≥ 1000ms`：精确提取实际覆盖的尾部视频区间。

### 8.2 右端规则

- 与下一个普通 Clip 开头重叠 `< 1000ms`：自动缩减到边界，只取得下一个 Clip 当前结果的首帧。
- 与下一个普通 Clip 开头重叠 `≥ 1000ms`：精确提取实际覆盖的开头视频区间。

`1000ms` 恰好归入视频区间模式。连接 Clip 跨过临界值时，状态标签、锁定输入、模型候选、运行模式和参数面板立即更新。

### 8.3 输入组合

| 左端 | 右端 | 连接模式 | 模型要求 |
|---|---|---|---|
| 尾帧 | 无 | 尾帧续写 | 支持首帧或图片续写 |
| 视频区间 | 无 | 视频向后接续 | 支持视频参考或视频续写 |
| 无 | 首帧 | 向首帧生成 | 支持结尾帧约束 |
| 无 | 视频区间 | 向后段视频衔接 | 支持视频参考或视频编辑 |
| 尾帧 | 首帧 | 首尾帧连接 | 支持首尾帧生成 |
| 视频区间 | 首帧 | 视频接续到结尾帧 | 支持视频参考与结尾帧组合 |
| 尾帧 | 视频区间 | 起始帧接入视频 | 支持起始帧与视频参考组合 |
| 视频区间 | 视频区间 | 双视频连接 | 支持双视频或多视频参考 |

连接 Clip 至少需要从一侧普通 Clip 自动取得输入；左右两侧都没有命中时才禁止运行。没有兼容模型时显示“暂无兼容模型”和具体冲突，禁止运行。系统不得删除已经命中的某一侧输入后偷偷放宽模型候选。

连接 Clip 自动产生的帧和视频区间在垂直输入清单中显示为锁定项目，不能删除、换序或覆盖。其他手动输入是否允许，由当前模型剩余输入能力决定；不支持的输入保留为禁用草稿，运行时不提交。

### 8.4 同轨覆盖与播放

- 连接 Clip 未生成时，蓝色卡片只是计划覆盖层。底下已有普通视频的区域继续播放普通视频，空白区域播放黑场。
- 连接 Clip 生成成功后，它在自己的完整时间区间内拥有播放优先级，底下普通 Clip 的被覆盖部分不重复播放。
- 连接 Clip 的拖动和缩放只改变生成关系，不破坏底下普通 Clip 的位置、裁剪和结果。

## 九、动态模型与参数

通用导演台不维护独立模型表。每个 Clip 复用普通视频节点的统一能力计算：

```text
手动输入
+ 时间线自动输入
→ 输入类型、数量和角色
→ 兼容平台
→ 兼容模型
→ 兼容运行模式
→ 动态参数
→ 统一运行前预检
```

输入变化导致当前模型失效时，保留原选择和参数草稿、明确标红并要求用户重新选择，不能静默切换模型。模型 Schema 不支持的旧参数不得发送。

参数面板直接复用视频节点的能力档案渲染器：枚举、布尔、数值、自由文本和“使用平台默认”状态保持相同交互。当前 Clip 的参数存入 `generation.params`，提交时映射到共用执行结构的 `capabilityParameters[model_id]`；可选参数处于“使用默认”时不得出现在平台请求中。切换模型时按模型保存参数草稿，旧模型的字段不能反向过滤新模型候选，也不能混入新模型请求。能力档案中的时长参数同时决定 Clip 的时间线宽度。

个性化导演台使用同一过程，但候选来源变为已配置的 ComfyUI 工作流、RunningHub 工作流兼容配置或 RunningHub AI 应用 Schema。工作流未声明的输入角色不得根据字段名称猜测为可用。

## 十、运行与结果

- “运行当前”只提交当前选中 Clip。
- “批量运行”提交尚无可用结果或被用户选中的 Clip；第一阶段不自动建立相邻普通 Clip 依赖。
- 连接 Clip 必须等待它引用的左右普通 Clip 已有明确当前结果，才能计算尾帧、首帧或视频区间。
- 每次运行建立独立 `runRef/taskId` 和结果版本；同一个导演台允许多个互不依赖的普通 Clip 并行。
- 主动停止只停止当前运行等待和结果回写；上游没有取消接口时必须说明任务可能继续。
- 失败保留 Clip 和已有结果，并显示具体原因；失败不等于取消。

运行前错误必须写入画布日志，包括缺少输入、无兼容模型、时间区间无效、上游结果缺失、参数不合法和适配器不可用。

## 十一、分片导出

导演台不把时间线拼成最终视频。导出时收集所有选择了结果版本的普通 Clip 和连接 Clip，统一视为 Clip。

排序键固定为：

```text
第一顺序：start_ms + duration_ms / 2（Clip 时间中点）
第二顺序：start_ms
第三顺序：created_at
第四顺序：稳定 Clip ID
```

文件统一命名，不暴露 Clip 类型：

```text
工程名-clip-001.mp4
工程名-clip-002.mp4
工程名-clip-003.mp4
```

导出包同时包含一份清单，记录文件名、Clip ID、普通/连接类型、开始时间、结束时间、中点、时长、当前结果版本和生成快照。清单只帮助追溯，不改变文件排序。

## 十二、旧 MiniMax 节点迁移

现有 `smart-minimax` 不能直接删除。迁移步骤为：

1. 保存迁移前画布快照。
2. 保留节点 ID、位置、尺寸和已有连线。
3. 把现有 `segments` 转换为普通 Clip，把 `refs/materials` 转换为工程素材引用。
4. 把现有 ComfyUI/RunningHub 设置转换为 MiniMax 个性化适配器配置。
5. 把分段 `result/results` 转换为 `result_versions/current_version_id`。
6. 迁移成功后只读取新导演台字段；旧字段仅存在于迁移前备份和旧文件导入适配器。

不能为了兼容旧数据继续长期双写新旧时间线结构。

## 十三、错误与异常处理

- 连接 Clip 左右两侧都没有命中普通 Clip：指出缺少时间线来源，不生成伪输入。
- 已命中的普通 Clip 没有结果：连接 Clip 保持可编辑，运行按钮禁用并说明需要先生成哪个 Clip。
- 普通 Clip 切换结果版本：依赖它的连接 Clip 标记“来源结果已变化，需要重新生成”，不能继续假装结果仍有效。
- 远程素材无法读取真实时长或帧：阻止提取并记录具体素材。
- 素材从工程库移除但仍被引用：阻止删除或要求用户确认解除哪些引用。
- 时间线上两个连接 Clip 重叠：第一阶段禁止重叠并显示冲突范围，避免播放和导出优先级不确定。
- 保存重开后必须恢复选中 Clip、播放头、输入顺序、参数草稿、结果版本和连接计算结果。

## 十四、验收范围

### 14.1 交互

- 连线素材只进入工程库；资产库素材可以直接拖到工程库或指定 Clip。
- Clip 素材在 Clip 下方按类型垂直罗列。
- 普通 Clip 可以留空白间距，空白预览为黑场。
- 连接 Clip 与普通 Clip 同轨覆盖，不出现第二条连接轨。
- 左右两侧在 `<1 秒`、`=1 秒`、`>1 秒`三种边界下输入判断正确。
- 连接 Clip 跨越临界点后模型候选和锁定输入立即变化。

### 14.2 数据与运行

- 通用 Clip 与普通视频节点对同一输入组合得到相同模型候选和预检结果。
- 个性化 Clip 只提交工作流或 AI 应用 Schema 明确支持的字段。
- 重新生成增加版本，切换版本后预览、连接来源和导出同步更新。
- 保存重开、复制画布、迁移旧 MiniMax 节点后引用稳定。

### 14.3 导出

- 普通与连接 Clip 混合后严格按时间中点排序。
- 所有文件统一使用 `工程名-clip-NNN`。
- 相同时间中点时排序稳定。
- 导出只包含独立片段和清单，不自动拼接、混音或添加转场。

## 十五、后续记录：角色—音色绑定

该能力已经讨论但明确延后，不进入第一阶段：

- 在导演台工程级建立角色视觉素材与音色素材的全局映射。
- Clip 使用角色视觉素材时，按稳定资产 ID 自动带入对应音色。
- 相同内容不同 ID 时可用 SHA-256 识别副本；不得用外观相似度自动判断角色。
- Clip 信息栏明确显示“角色视觉参考 → 音色参考”。
- 只有接口 Schema 或适配器证据证明支持角色音色关联时才能运行；不得只发送无关联素材后宣称已绑定。

后续启用前需要单独确认数据结构、模型能力证据、工作流字段映射、无音频模型的处理和界面范围。

## 十七、第一阶段实际接口与缓存

- `POST /api/smart-canvas/director-reference`：在连接 Clip 真正运行前，从本地来源视频提取首帧、尾帧或精确时间片段。
- `GET /api/smart-canvas/director-reference/{filename}`：读取可重建引用；文件位于 `cache/director-references/`，不登记为用户素材。
- `POST /api/smart-canvas/director-export`：按 Clip 时间中点排序并打包独立片段和 `manifest.json`。
- 旧 `/api/smart-canvas/minimax-export` 只保留历史兼容，新版导演台界面不得调用。

缓存键由来源文件内容哈希、操作和时间范围共同决定。首尾帧/片段提取使用 `pathlib` 与子进程参数列表，不能拼接 Shell 字符串，从而保持 macOS 与 Windows 路径兼容。
